# Folio 安装包

folio 是一个电子书与文档阅读器：正文的排版（首行缩进、居中、局部字重、插图、目录、
竖排）由它自己的引擎算，不嵌浏览器、不用 WebView。

这个仓库放的是**发布产物**：每个版本的安装包、校验和与更新日志。源码不在这儿，目前也不
公开，原因写在下面「许可与源码」那一节。

## 去哪儿下载

开 [Releases](https://github.com/panzhifu/folio-releases/releases) 那一页，最新一版排在最上。
每一版的正文里有三样：**这一版改了什么**、**这一版的已知限制**、以及那份 `sha256sums.txt` 的
内容。限制那一档每次都逐条写全，不在这里重复，因为各版会漂。

包名里就写着它给谁用：

| 你的机器 | 拿哪一个 | 要知道的 |
|---|---|---|
| Linux x86_64 | `folio-<版本>-linux-x86_64.tar.xz`（解压即用）、`folio_<版本>_amd64.deb`、`folio-<版本>-x86_64.rpm` | `.deb` 与 `.rpm` 的依赖是打包时从编出来的二进制现算的（`dpkg-shlibdeps` / `find-requires`），没有手写的依赖表 |
| Apple Silicon 的 Mac | `folio-<版本>-macos-arm64.zip` | **未签名、未公证**（没有开发者证书）。第一次打开要在「系统设置 → 隐私与安全性」里允许一次，或者按住控制键点它 |
| 64 位 Windows | `folio-<版本>-windows-x64.exe`（安装器）、`folio-<版本>-windows-x64.zip`（便携版，解压即用） | 这一族的包没有在真机上验证过，撞上问题请走下面的「反馈」那一条 |
| 64 位 Android | `folio-<版本>-arm64-v8a.apk` | 要求 **Android 8.0（API 26）以上的 64 位设备**。32 位的机器装不上 |

只出上面这四端。HarmonyOS 与 iOS 不在发布矩阵里 —— 工程目录是齐的，但没发，不是漏了。

## 验一下包

正文末尾挂着的那份清单就是 `sha256sums.txt`。把它和下载回来的文件放同一个目录：

```bash
sha256sum -c sha256sums.txt
```

## 能读哪些格式

EPUB、FB2、MOBI / AZW / AZW3（KF7 与 KF8，含 hybrid）、AZW4、PDF、DOCX、老 `.doc`、ODT、
RTF、CHM、纯文本与 Markdown、HTML / HTMLZ / MHTML、漫画包 CBZ / CB7 / CBR / CBT、DjVu、
PDB / PalmDoc。导入那一屏能选中的，就是它认得下的。

三句实话：

- **PDF、AZW4、DjVu 这三族只有页面，没有文字层** —— 选中、批注、听书在这三族上是空的。
- **加密的包要密码才能读**，而加密 RAR（`.cbr`）目前没有输密码的入口。
- **听书只有 Linux 与 Android**：它用那两端系统自己的语音合成，macOS 与 Windows 上那一格
  不会出现。

## 界面语言

简中、繁中、英文、日文、韩文、德文、西班牙文、法文、俄文九种。**默认是简体中文**
（不去探系统的语言），在「设置 → 关于 → 界面语言」里换。书的正文是什么语言不影响这一条。

## 检查更新

「设置 → 关于 → 检查更新」。folio **只在你按下那颗按钮之后**才联网：不做开机检查，不发任何
使用统计。检查到的新版本会连它的更新日志一起给你看。

- **Android**：可以在应用里装。folio 先把包下载下来、校验它的 SHA-256 与本仓库公开的那份
  对得上，再交给系统安装器。第一次会让你授予「安装未知应用」的权限，而授权要在系统设置里
  完成 —— **回去之后请再点一次「检查更新」**，folio 不会自己接着跑，那是为了让每一次安装都由
  你按下。
- **Linux / macOS / Windows**：只告诉你「有新版本了」并打开这一页，不动正在运行的程序。
  桌面软件的替换该由你或你的包管理器决定，不是一个阅读器的分内事。

## 出问题怎么反馈

同一屏有一颗「反馈日志」：它把日志整理成一份带版本号、平台、语言与目录路径的文件。

- **Android**：交给系统的分享面板，邮件、网盘、聊天工具都行。
- **桌面**：复制一份到「下载」目录，同时打开一封写给作者的邮件草稿。**草稿带不了附件**
  —— 那是 `mailto:` 协议本身没有那个位置，不是没做完。路径写在正文里并复制进了剪贴板，
  把那个文件手工附上就行。那台机器上没有邮件应用时，副本照样落盘，地址与路径一起进剪贴板。

**一句提醒：那份日志里可能出现你看过的书名与文件路径。** 那是排障需要的东西，去不掉。
不想让它们出现在反馈里，就别发那份日志。

## 许可与源码

folio 自己声明 **MIT**。但当前**源码不公开** —— 发出去的是二进制。挂着 MIT 却拿不到源码
不是漏了一环，是这一版的现状；哪天要把源码放出去，改的是这一节，不是把安装包撤掉。

folio 用到的第三方库的版权与许可文本随**桌面三端**的每一个安装包发布：

| 端 | 那份文本在包里的哪儿 |
|---|---|
| Linux `.tar.xz` / `.rpm` | `share/doc/folio/THIRD-PARTY-NOTICES.txt` |
| Linux `.deb` | `/usr/share/doc/folio/THIRD-PARTY-NOTICES.txt.gz`（按 Debian 的规矩压成 gz） |
| macOS | `Folio.app/Contents/Resources/THIRD-PARTY-NOTICES.txt` |
| Windows | 安装目录里的 `THIRD-PARTY-NOTICES.txt`，安装器最后一页有一条勾选项直接打开它；便携版那份在 zip 里与 exe 并排 |
| Android | **这一版的 APK 里没有带，应用内也还没有读它的那一格** —— 手机上目前只能在上面那个发布页读 |

这一条与上面那纸 MIT 无关 —— 是那些依赖自己的许可证在二进制分发下的要求，不因本软件是否开源而免除。
