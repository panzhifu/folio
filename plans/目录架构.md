| foundation | ✓ | ✗ | ✗ | ✗ | ✗ | ✗ |
| services | ✓ | ✓ | ✗ | ✗ | ✗ | ✓ |
| components | ✓ | ✓ | ✓ | ✗ | ✗ | ✓ |
| features/<cap> | ✓ | ✓ | ✓ | 只准自己 | ✗ | ✓ |
| shell | ✓ | ✓ | ✓ | ✓（只走 `mod.rs` 公开缝） | ✓ | ✓ |
| host/platform | ✓ | ✓ | ✓ | ✗ | ✗ | ✓ |

纵切内部：

| 从 \ 到 | model | view | components | overlay | motion |
|---|---|---|---|---|---|
| model | ✓ | ✗ | ✓（只持 `Entity` 句柄） | ✓（只持句柄） | ✓（纯函数） |
| view | ✓ | ✓ 同层 | ✓ | ✗ | ✓ |
| components | ✓ | ✗ | ✓ | ✗ | ✗ |
| overlay | ✓ | ✗ | ✓ | ✓ | ✗ |
| motion | ✓（只读） | ✗ | ✗ | ✗ | ✓ |

**两条例外**（写在这里，免得后来的人当成违规去改）：

① `model/measure.rs` 碰 `TextSystem`，因为 `chapter_layout` 与 `session` 都要量字。它是**排版的度量**，
不是界面，所以留在 `model/`。同一条精神：`scene.rs` 只产出绘制单元，但它只服务渲染 → 留 `view/`。

② `model/` 会持 `Entity<NoteEditor>` / `Entity<ImageViewer>` 这类组件句柄（`session.rs` 现在就持着）。
判据是「它只是句柄，不调 `render`」，所以不构成 `model → view` 的依赖。

**可执行的边界检查**（放进 CI 或提交前手跑）：

```bash

rg -n 'features::' crates/folio-app/src/ui/components/ && echo FAIL-1
# 2 纵切不许摸兄弟纵切的内部三层

rg -n 'Entity<|Service\b' crates/folio-app/src/ui/foundation/ && echo FAIL-3

# 5 shell 只许从 features 的 mod.rs 公开缝取类型
```

## 八、搬迁顺序与批次

> 仓库走 jj。每批一个提交：`jj describe -m "…"` → 门禁 → `jj new`。**不要** `git add/commit`。
> 门禁：`cargo fmt --all -- --check` → `cargo check --workspace --all-targets` →
> `cargo test --workspace --lib`。

| 批 | 内容 | 改代码？ | 状态 |
|---|---|---|---|
|---|---|---|---|
| 0 | `super::` 深度归一（只读），确认搬迁半径 | 否 | ✅ |
| 1 | `foundation` / `services` / `components` 三块立起来 | 纯移动 + 193 处路径 | ✅ 已提交 |
| 2 | `features/reader` 四层 | 纯移动 + ~262 处 `super::` | ✅ 已提交 |
| 3 | `shelf` / `settings` / `stats` / `notes` / `welcome` | 纯移动 | ✅ 已提交 |
| 4 | 页面瘦身 | 提参数，不改式子 | 🟡 部分：`reading_page`→`regions`、`shelf/view`→`toolbar`+`sheets`+`grid`、`stats/view`→`sections`；`toc_panel` / `selection` / `image_viewer` / `chapter_layout` / `bottom_sheet` 未拆 |
| 5 | 换 gpui-kit 已有的组件（设置屏为主） | **改外观**，单独冒烟 | ⛔ 评估后不做（理由见 §五） |

`super::` 的处理规则（按组，一批一组）：

| 文件组 | 深度变化 | 规则 |
|---|---|---|
| `reader/*.rs → model/` | +1 | `super::` → `super::super::`；指向 `reader::` 的保持 |
| `reader/*.rs → view/` | +1 | 同上 |
| `reader/*.rs → components/` | +1 | 同上 |
| `modules/*.rs → model/` | 不变（2→2） | `super::super::x` → `super::x`（现在 `x` 也在 model 里） |
| `turn_animation/* → motion/turn_animation/` | +1 | 内部 `super::` → `super::super::`；`super::super::chrome` → `crate::ui::features::reader::model::chrome` |
| `components/*.rs` 里指向 `reader::` 的 | — | 一律改绝对路径 `crate::ui::features::reader::model::…` |

**降熵建议**：搬 `components/` 那五个文件时，顺手把它们的 `use super::…` 全换成
`crate::ui::features::reader::model::…` 绝对路径 —— 这几处以后不再随深度变化而改。

### 批 6 · 测试放法统一

- 常规：`mod.rs` 末尾内联 `#[cfg(test)] mod tests`。
- 超长：`foo/tests/{主题}.rs`，一个主题一个文件。
- `crates/folio-core/tests/` 保留，只放跨模块公共缝的用例。

## 九、每批的门（缺一不可）

```bash
cargo fmt --all -- --check
cargo check --workspace --all-targets
cargo test --workspace --lib
cargo test --workspace --lib -- --list > /tmp/t-$N.txt && diff /tmp/t-0.txt /tmp/t-$N.txt   # 纯移动批必须为空
jj diff --stat                                                    # 纯移动批只该有 rename
```

## 五、为什么第 5 批（换 gpui-kit 组件）评估后不做

三处候选逐个看了源码，结论都是「会改外观」或「与设计意图冲突」，不能在没有真机冒烟的情况盲改：

| 候选 | 结论 |
|---|---|
| `settings/compact.rs` 的行/卡片 → `SettingItem` | **不做**。桌面已经用 `SettingItem`（`view/mod.rs` 的 `setting_page` 映射），而手机那份是**刻意的另一套版式**（Apple 式分组列表，文件头写着理由）。替掉等于把两端并成一样，是设计变更不是重构。 |
| `hairline()` → `component::separator::Separator` | **不做**。我们是 0.5 逻辑像素的「发丝线」，`Separator` 是 1px；全应用二十多处都在用，换过去是整屏观感变化。 |
| `empty_state()` → `component::empty::Empty` | **不做**。`Empty` 自带 media / title / description 三段与自己的间距，我们那一版是「一行标题 + 一行 muted」的满幅居中。替换要重排三处空状态页。 |

已经**在**用 gpui-kit 的：`Button` / `Input` / `Select` / `PopupMenu` / `DropdownMenu` / `Setting*` /
`BarChart` / `RadarChart` / `Progress` / `NavStack` / `base::Sheet`（`BottomSheet` 只借宿主的焦点陷阱
与返回键，拖动与弹簧自己接 —— 文件头写了为什么不直接用 `component::Sheet`）。

要做第 5 批，前置条件是**真机**（Meizu 20）能并排对比，而不是在这里按代码猜。
