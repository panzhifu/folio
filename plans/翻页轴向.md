# 翻页轴向：手势的轴由动画档决定

**一句话**：现在「往哪根轴划算翻页」由**手指**决定（`dominant(dx, dy)`），与读者选的动画档无关；
而且同一笔竖向拖动会同时穿过**跟手翻页**与**滚动/滚轮翻页**两条路。这份计划把轴的决定权收到
`PageTurnStyle::axis()` 一处，并让一次手势只落到一个动作上。

---

## 一、现状：一次竖向拖动要经过几处

真机事件来自 `gpui-pre 0.3.9` 的识别器（`gestures.rs`）：手指走过 `touch_slop = 8px` 才发第一条
`ScrollWheelEvent`（`TouchPhase::Started`，**带住从按下点算起的整截增量**），此后一路只发**锁了轴**的
`Moved`，抬手再补 `Ended`；甩得快时抬手后还有一串**惯性** `Moved`（`Momentum`），最后补一条 `Ended`。

到了 folio，入口只有一个（`view.rs` 的 `on_scroll_wheel` → `ReaderSession::on_scroll`，
`modules/navigation.rs:342`），但里面分叉成两条：

```
on_scroll
├─ swipe_scroll(touch_phase, dx, dy)          swipe.rs:146   第一条：跟手翻页
│   ├─ swipe_walk → claim_swipe(dx, dy)        :174 / :211   按**手指**定轴 → dominant()
│   │   └─ swipe_geometry(drag)                :126          拿「手指轴」去比「动画轴」
│   └─ swipe_release → set_page(target)        :279 / :307   松手落页（绕过 turn()）
└─ 普通滚动臂                                  navigation.rs:395 起   第二条：滚动 / 滚轮翻页
    ├─ 连续：scroll_y -= dy                     :422
    └─ 分页：wheel_accum -= dy，过半屏翻一页     :425-:446   自己一套章界判断
        └─ cancel_turn()                        :414        这一笔会掐断正在走的动画
```

`turn()`（`navigation.rs:88`）自称「一次离散翻页的唯一入口」，但上面第二条根本没走它，`swipe_release`
也只借了它一半（认领时问过策略，落页时自己 `set_page`）。

## 二、四条具体缺陷

### D1 · 轴由手指定，不由动画档定（这是要改的那条）

`swipe_geometry`（`swipe.rs:126`）返回的是 `(这一档的轴, 按**这一笔**的轴量的距离, rtl)`，
`claim_swipe`（`:211`）随后只判「轴合不合」——不合也照样认领，只是不摆第二张纸（`:242`），
到松手照样翻一页。

结果：**读者选了横向动画（Slide / Cover / Curl），竖着划也翻页**；反过来选了 `SlideUp`，
横着划也翻页。轴在这里只是个「跟不跟手」的开关，不是「这根轴算不算数」的门。

### D2 · 松手后的惯性会掐断收尾动画、还可能再翻一页 ★「竖向滑动影响竖向翻页」的现场

`swipe_release` 里 `self.swipe.take()`（`:280`）之后，跟手态就没了。惯性那一串 `Moved`
于是走 `swipe_walk → swipe.is_none() → return false`，落进 `on_scroll` 的普通臂：

1. `navigation.rs:414` `self.cancel_turn()` —— 松手那一腿的动画**当场落定**（读者看到「啪」一下到位，
   而不是滑完）；
2. `:425` `wheel_accum -= dy` —— 竖向惯性继续攒，攒过半屏（`viewport * 0.5`）就**再翻一页**。

分页 + `SlideUp` 时这两条都最明显：手指向上划一次，纸滑到一半，松手后动画被惯性掐断，
随后惯性又推着翻了一页。`Ended`（零增量）也走同一条路。

### D3 · 同一笔手势两条语义（认领失败就降级成滚动）

`claim_swipe` 会主动放弃：没过 `SLOP = 16`（`:217`）、定不出轴、`swipe_geometry` 给 `None`、
策略给 `TurnPlan::None | Scroll`（`:231-:236`）。放弃时它把 `self.swipe = None`（`:222`/`:230` 等），
于是**这一笔剩下的每一个增量**都进普通臂 —— 该翻页的一笔变成滚动，或者变成滚轮翻页。

另外 `touch_slop(8) < SLOP(16)` 是天生对不齐的：每条 `Started` 都带着 8–16px 的增量，
而那时 `passed()` 还是假，所以**每一笔的开头一小段必定漏进普通臂**（连续模式里这是「内容先跟手」，
不算错；分页模式里它是「半屏阈值的一小口」，通常随后被 `claim_swipe` 里的 `wheel_accum = 0.0` 清掉，
但认领被 D3 拒掉时不清）。

### D4 · 「滚轮」与「触摸拖动的后续」在同一根轴上抢同一件事

分页模式里 `wheel_accum` 的半屏翻页对**鼠标滚轮**是好用的，对**手指**是 D2。而「这一条事件是
滚轮还是触摸」其实可判：触摸一笔必以 `Started` 开，鼠标滚轮从不发 `Started`（平台给的是默认的
`Moved`）。这一格判据现在没人用。

## 三、目标设计

### 不变量

1. **翻页轴只有一个来源**：`PageTurnStyle::axis()`。摆法决定它存不存在，档位决定它是横还是竖。
2. **一笔手势只落到一个动作**：`Turn`（跟手/不跟手）、`Scroll`（仅连续）、`Ignore`。不存在
   「先 Ignore 一半，再 Scroll 一半」。
3. **惯性尾巴归发起那一笔**：松手后同一笔的 `Moved` / `Ended` 由翻页那一趟自己吃掉，不落到滚动臂。
4. **滚动轴只存在于连续摆法**：分页 / 双页里没有「滚」这件事，非翻页轴的手势 = 无操作。

### 判定表

| 摆法 | 档位 | 翻页轴 | 跟手 | 竖向拖动 | 横向拖动 | 滚轮 |
|---|---|---|---|---|---|---|
| 连续 | 任意 | — | — | 滚动（`scroll_y -= dy`） | 无操作 | 滚动 |
| 连续 | `Scroll` | — | — | 滚动（这一档就是补间本身） | 无操作 | 滚动 |
| 分页 / 双页 | `Slide` / `Cover` / `Curl` | 横 | 是 | **无操作** | 跟手翻页 | `Step(±1)` |
| 分页 / 双页 | `SlideUp` | 竖 | 是 | **跟手翻页** | **无操作** | `Step(±1)` |
| 分页 / 双页 | `None` | 竖（建议，见待定 ①） | 否 | 翻页（不播动画） | 无操作 | `Step(±1)` |
| 分页 / 双页 | `Scroll`（不适配） | 竖（按 `None` 处理） | 否 | 翻页（不播动画） | 无操作 | `Step(±1)` |

滚轮永远是「上一步 / 下一步」，与轴无关：它不是手势，读者转它就是要翻页。

### 形状

```rust
// turn_animation/mod.rs
impl PageMode { fn page_axis(self, style: PageTurn) -> Option<Axis> }   // 分页/双页才 Some

// swipe.rs
pub(in …reader) enum ScrollRoute {
    Turn { axis: Axis, intent: TurnIntent, follow: bool },
    Scroll { dy: f32 },          // 仅连续
    Swallow,                     // 这笔归翻页管，但这一帧不动（惯性尾巴、轴不对）
    Pass,                        // 真的不归阅读页（滚轮在连续里也走 Scroll，所以 Pass 很少用）
}
pub(in …reader) fn route(gesture: GestureState, mode: PageMode, style: PageTurn, dx: f32, dy: f32) -> ScrollRoute
```

`on_scroll` 只剩搬运：`Started` 开笔、`Moved`/`Ended` 交给 `route`、按下表的答案改状态。
`route` 是纯函数，表驱动测试直接钉判定表。

## 四、改造步骤（每步可独立提交、独立验收）

### 步 1 · 轴归档位（最小改动，先止血 D1）

- `swipe_geometry` 去掉「按手指轴量距离」那半：距离一律按**动画轴**量（竖档取 `viewport`，横档取
  `content_bounds.width`）。
- `claim_swipe` 增加一条：`dominant(dx, dy) != page_axis` → **不认领**（`self.swipe = None`），
  让这一笔去走续下的路（步 2 之后是 `Swallow`）。
- 落页仍走 `swipe_release`，行为对「轴合」的那一半完全不变。

验收（`swipe.rs` 内联测试）：
- `only_the_page_axis_claims`：横档 + 竖划 → 不认领；竖档 + 横划 → 不认领；各自轴合则认领。
- `the_distance_is_measured_along_the_page_axis`：竖档竖划 1/3 屏 → `snap` 为真（横着的那条旧断言改掉）。

### 步 2 · 手势路由表（D3、D4）

- 引入 `ScrollRoute` 与 `route(...)`，把 `on_scroll` 里那三条 `if` 换成一个 `match`。
- 分页臂删掉 `wheel_accum` 与 `threshold`：滚轮（`Moved` 且无进行中的一笔）直接
  `turn(TurnIntent::from_delta(-dy.signum()))`，**不累积**。
- 非翻页轴的手势 → `Swallow`（不再降级成滚动）。

验收：
- `route` 的判定表测试（6 档 × 3 摆法 × 2 轴，逐格断言）—— 这是这份计划的主断言。
- `a_vertical_stroke_on_a_horizontal_style_does_nothing`：横档 + 竖划 → 页号不变、`scroll_y` 不变。
- `the_wheel_never_accumulates`：连续 4 条半屏的 `Moved` → 只翻 1 页（现状会翻 2 页）。

### 步 3 · 惯性尾巴归这一笔（D2）

- `SwipeTrack` 增加 `released: bool`（或让 `swipe` 保留到 `Ended` 之后由下一帧清掉）：
  `swipe_release` 之后同一笔的 `Moved` 一律 `Swallow`，直到那条 `Ended`。
- `on_scroll` 的 `cancel_turn()`（`:414`）只在 `Scroll` 这一支里调 —— 分页 / 双页不再因为一条
  滚动事件掐断动画。

验收：
- `momentum_after_a_swipe_does_not_turn_again`：跟手 + 松手 + 5 条惯性 `Moved` → 只翻 1 页。
- `momentum_does_not_cut_the_release_animation`：松手后 `self.turn` 仍是 `Released`（没被 `cancel_turn`）。

### 步 4（可选）· 并进 `TurnPlan` / `Target`

把 `ScrollRoute::Turn` 直接产出 `Target`（见讨论中的 B 方案），`turn()` 与手势路共用一句
`apply(target)`。这一步与「两套翻页动作」的收敛是同一件事，做完分页里只剩一个写 `self.page` 的地方。

## 五、真机冒烟（Meizu 20）

1. 分页 + `SlideUp`：向上划一页 → 纸跟着手指走，松手滑完，**不**多翻一页。
2. 分页 + `SlideUp`：横着划 → 画面完全不动。
3. 分页 + `Slide`：竖着划 → 画面完全不动；横着划 → 跟手翻页。
4. 分页 + `None`：竖着划 → 直接翻页，无动画。
5. 连续 + `SlideUp`：上下划 = 滚动，不出现第二张纸。
6. 分页 + 鼠标滚轮（桌面）：一格一页，快速连转不跳页。
7. 章末竖向跟手：松手后照旧整趟跨章滑动，不被惯性掐断。

## 六、待定

① **`None` 档的轴**：建议当竖轴（与默认摆法「上下滚动」、默认档 `None` 的手感一致）。
若希望 `None` 保留「两根轴都翻」，那就是本计划唯一保留的双轴档，需要在表里显式写明。

② **`Scroll` 档在分页里**：现在配置里可以是 `Scroll` 而摆法是分页（`settings/typography.rs` 有意不筛，
底栏 `page.rs:885` 有意筛 —— 两处口径不同但都有注释）。步 1 之后它按 `None` 处理（竖轴、不播动画）。
另一个选择是切成 paged 时把配置退回 `Slide`（写配置，读者会看到选项自己变了）。

③ **`SLOP = 16` 是否该跟 `touch_slop = 8` 对齐**：现在开头那 8–16px 必漏。步 2 之后它只影响
「连续模式里内容跟手的起点」，可以保留；若真机上觉得点按太容易被判成拖动，就把 `SLOP` 调到 8。

④ **速度判据**：`snap` 现在只看距离过没过 1/3 屏，不看速度（`swipe.rs:112` 的注释说这一版没有
可靠的逐帧时间戳）。`Momentum` 那条已经在识别器里算了速度，若真机抱怨「轻轻一甩也该翻」，再补。

## 七、不做的事

- 不改 `turn.rs` 的章界决策（`PagingStrategy` 保持原样，步 4 之后再谈 `Target` 化）。
- 不改 `turn_animation/` 里六档的几何（横竖位移、裁剪、阴影都不动）。
- 不给连续摆法做「横向手势 → 换章」（读者没有这个期待，加了就是新的双轴）。
