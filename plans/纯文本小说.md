# 纯文本小说（`.txt`）的解析

一份小说 `.txt` 进来之后要发生的事，按「谁说了算」排：**文本本身说了算**（编码、章标记），
**规则表说了算**（哪些写法算一章、书名的别名、阈值），**代码说了算**（不变量与算法）。
这份文档记的就是这三者的边界，以及下一步该动哪一条。

## 现状

| 环节 | 落点 | 状态 |
|---|---|---|
| 判定放行 | `format/sniff.rs`（三层：扩展名 / 魔数 / 容器） | 已落地 |
| 字节 → 文本 | `format/charset.rs` 的 `read_plain`：BOM > 严格 UTF-8 > 白名单内的码页判定 > UTF-8 | 已落地 |
| 规范化 | `format/text.rs` 的 `normalize`（**锚点坐标系就是它的产物**） | 已落地 |
| 分章 | `format/novel/{rules,detect}.rs`，四条否决门固定顺序 | 已落地 |
| 目录 | `FlowDoc.toc`（走现成 `books.toc_json`，无迁移） | 已落地 |
| 章标题渲染 | 切章时注入 `# `，由 `xhtml::from_plain_text` 画成 `<h*>` | 已落地 |
| 书名 / 作者 / 简介 | `book_info` 只读头部那一块，按 `meta` 的别名表 | 已落地 |
| 读者可编辑的规则文件 | 配置三层 + provenance + 恢复出厂 | **计划** |
| 分卷的第二层目录 | `volumes` 那族认得出来但不切 | **计划** |
| 站点水印行 | 未处理 | **可省（等一本真书）** |

## 边界：什么进数据，什么留在代码

这条线不是审美，是被真书和「读者改坏一个字符」两种事故画出来的。

**该是数据的，已经全是数据**：模式族与固定名（`markers` / `volumes`）、中文数字的字符集与
两档读法开关（`numbering`）、四条门的阈值（`gates`）、头部行数与别名表与括号对与去噪词
（`meta`）、以及每条规则的**正例与反例**（`examples`，见下面步骤二）。加一门语言 = 加一份
JSON，不改代码。

**留在代码的两类，各自理由不同：**

一、**不变量**。注入 `# ` 而不是删改那一行；标题超长时切下来的余下部分必须回到正文开头；
合法 UTF-8 永远先收、绝不交给探测器判码页；头部没说话就留空，不许猜作者。这四条一旦进了
JSON，读者改一个字符就能让引擎吞正文、或让进度指到隔壁一章，而屏幕上看不出来。规则可以
错，不吃字不能错 —— 它是锚点坐标系的前提。

二、**算法**。按位值与按单位混合读数、目录链要求「号必须前进」、递增筛选。把它们变成数据
只能靠发明一门 DSL 再写解释器执行，那一层比现在的两百行更贵。而且**没有样本支持**：真书
教出来的三处修正里，两处是数据（白圈当零、编号规则限长），一处是收紧数据里的模式，
**零处要求改算法**。

## 步骤

### 一 · 位值表进数据 —— 消掉最后一个双份事实

`numbering.digits` 现在存的是「哪些字符算数字」，而每个字符**值多少**写在 `detect.rs` 里。
后果是实打实的：上次补白圈 `○`，既要改数据的字符集、又要改代码的 `value()` 分支 —— 加一种
数字要动两处，而这两处会漂。做法：`digits` 从集合升级成「字符 = 值」的表，单位（十百千万）
同样进表；代码只保留「按位值读」与「按单位累加」这两条算法。

验收：删掉数据里某一格（例如把 `○` 从表里拿掉）时，那条 `一○`=10 的门必须红 —— 证明码里
不再有第二份表。

### 二 · 每条规则自带正反例，加载即自检

`markers` 每条加一格 `examples: { must_match: [...], must_not_match: [...] }`，`compile()`
当场跑一遍，不通过的条目**只作废那一条**并留一句指名道姓的 warn。价值有实证：那次「编号」
那族吃掉一整本红楼（正文一句 `五六．又值人來回，…` 被读成第 56 章），修法是把长度上限写进
模式 —— 如果有这条自检，它属于**在数据里当场就红**，不必等到有人在真书上发现少了三十七章。

验收：把那条模式的 `\S{0,20}$` 去掉，加载自检就该报出「编号」这一条的正例反例不通过。

### 三 · 规则内容哈希进失效判据

`CompiledRules::content_hash` 已经在算，还没有读者。要接的是 `store::stale_reason`：生效那套
表的哈希变了，就把这本书认成「该重扫」—— 与 `INDEX_VERSION` 同一档，但不用每次调一个数都
发一版。理由写在 `ChapterLocator::Section` 那条注释上：库里存的是**序号**，规则一改进度就会
安静地指到隔壁那一章。

验收：换一份只有阈值不同的规则表（章数会变），`stale_reason` 要说出「规则变了」而不是
「索引版本旧」；而改一个跟分章无关的注释字段**不该**触发重扫（这也是为什么哈希要算在**规范化
之后的表**上，而不是原始字节上）。

### 四 · 读者那一层：三层 + provenance + 恢复出厂

`infra/config.rs` 已经把「每一项由哪一层定下来」解过一次（`Layer::{Default, File, Env}` 与
旁路表），规则文件走同一套，不新发明一条链。要给的：文件路径两端同口径、解不开就退回出厂并
在诊断里说清是哪一层生效、界面上一个「恢复出厂规则」。顺序有讲究 —— **步骤三在这之前**，
否则读者第一次改规则就是一次没有代价的静默漂移。

验收：写坏一个字符，书照开、按出厂分章、诊断那一格说出「生效的是出厂那份，因为读者那份
在某行某列解不开」。

## 明确不做

- **规则表达式 DSL**：把门的编排与读数算法也变成数据。没有样本要求它，而解释器是新代码。
- **水印行清洗**：先只标出来不删（删了就断了「分章不许吃字」那条不变量），且本机一本那样的
  真书都没有。
- **没标记的书按字数硬切**：那种书读者的诉求是「别切成一堆没有名字的小块」，不是「自动分章」。
- **在没有真语料的情况下调阈值**：八本公版已经见底，网文形态（`书名：` 头部块、水印、`番外`）
  仍只有合成样本，那部分阈值到有一本真网文再动。
