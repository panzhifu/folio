# Locator：阅读位置与批注的坐标系

> 状态：**设计稿**，与 `plans/导入管线.md`、`plans/阅读管线.md`、`plans/基础设施.md` 并列。
>
> 这三份都引用 `Locator` 却没有一份定义它：阅读管线的四个对外函数以它为入参与返回、
> 导入管线用每章字数表支撑它的百分比、基础设施的版本戳规矩第一条就要落在它的序列化串上。
> 本文补这一块。
>
> **本文只定「内容坐标」那一套。** 三套坐标（内容 / 文档几何 / 屏幕）的分工与两处换算规则在
> `plans/阅读管线.md` 的第二节，不在这里重复。

## 一、它是什么

**用一串数字指着书里的某一个地方。**

纸书可以写"第 87 页第 3 行"，因为纸质版面是钉死的。流式电子书**没有页这个客观存在**——同一本书在
手机上是 480 页，在平板上是 320 页。所以位置不是读出来的，是设计出来的。

一次完整往返，本文要定的就是这串数字长什么样、谁能比大小、明天还准不准：

```
存：读者此刻在 → (章的稳定身份, 章内第几个字) → 写进数据库
取：读那串数字 → 重排这一章 → 换算成这一代的几何 → 界面只拿到像素
```

**锚落库，派生量不落库。** 凡是会随版面变的数（页码、像素 y、屏幕行号）一律不存真相；
落库的必须是不随版面变的东西。这一条是整个设计的核心，其余都是它的细节。

## 二、规范单位与它的三条性质

规范单位：**章的稳定身份 + 章内字符偏移**（按字计，不按字节计——中文按字理解，字节会劈开
Unicode 代理对）。三条性质是它被选中的原因，也是必须守住的要求：

| 性质 | 怎么得到 | 谁依赖它 |
|---|---|---|
| **全序可比** | `(章序号, 偏移)` 的字典序；章序号取自章节表，不来自偏移本身 | 批注列表按阅读顺序排、跳章二分、"这条比那条靠前吗" |
| **可相减** | **全局字符进度** = 前面各章字数之和 + 章内偏移 | 阅读统计（今天读了多少字）、两个批注之间隔几字 |
| **百分比不依赖排版** | 全局字符进度 ÷ 全书总字数 | 进度条、剩余时间估算、书架上"读了 37%" |

第二条依赖导入落库的**每章规范化字数表**（`plans/导入管线.md` 的产物清单第 3 条）。那条与本文是互相
成就的：字数表之所以值得为它在导入时读一遍全书，就是因为这里要用它算进度；而这里的进度之所以
**跨设备显示同一个数**，就是因为它是数字数而不是算几何。

对照一条容易走错的路：KOReader 用「文档 y 坐标」充当可比较的量（xpointer 定位到节点后取
`toPoint().y`）。对它成立，因为它的主锚是 DOM 路径、拿不到一个自然的字符级偏移；但 y 需要排版才存在，
所以它不打开书就答不出进度。**本项目有章这个真实单位，不必走那条。**

一个必须承认的例外：全局字符进度依赖"哪些内容进入主流"这类设置（EPUB 的非线性流）。所以它是
**口径的函数**，口径变了它跟着变——这是它能接受的原因：变了也只是进度条差零点几，不会像锚那样
让批注画错位置。口径归属见第六节的版本戳。

## 三、存什么

一条位置数据五个字段，前四行都落库：

| 字段 | 内容 | 用途 | 谁读它 |
|---|---|---|---|
| `chapter` | 章的稳定身份（不是下标，见第七节） | 主锚 | 恢复、比较、分组 |
| `offset` | 章内字符偏移 | 精确定位 | 恢复、几何换算 |
| `mark` | 该偏移所在段落的结构位置：第几个 `<p>` 的第几字 | 章改版后的兜底锚 | 第四级降级 |
| `quote` | 覆盖到的原文（起止各若干字） | **双重身份**：给人看的摘要 + 重定位的指纹 | 笔记列表、第三级降级 |
| `format_rev` | 写下这行字时用的口径版本戳 | 判断要不要迁移 | 第六节 |

明确**不落库**的三样：页码、像素 y、百分比。要用的时候现算。

一条约束：`quote` 不许"顺手"从别处取。它是**读者当时看到的那串字**，必须与锚同一次事务写入；
从当前文本反查会静默修正历史，把"内容变了"这件事伪装成"批注还在"。

## 四、恢复：四级降级

按可靠性依次尝试，**每级都要报告它成功在哪一级**：

```
1 章身份 + 偏移        → 章在、偏移在界内、口径版本一致        → 精确
2 段锚（第 N 段第 M 字） → 章被重排但段落结构还在                → 精确
3 quote 指纹搜索        → 前两级都失败，靠上下文把位置捞回来      → 近似
4 全部失败              → **明确失败**：把这条标为"位置丢失"，
                          放在所属章的章首，界面标灰，等读者处置   → 失败
```

现有实现里已经有这条降级链（`folio_core::anchor` 的四级 `relocate`，以及 `Confidence` / `Relocated`
两个返回类型），本文不重造它，只补它缺的两样：第三级所需的 `quote` 字段、第四级所需的
"失败要可见"这条产品要求。

**不许假装成功。** 第 3 级命中后置信度必须一路带到界面：那条高亮旁边一个灰点，或笔记列表里一个
"位置可能不精确"的标记。理由是读者的信任成本——高亮漂到别的句子上，他会认为这个应用吞了他的笔记，
而这恰恰是最难复现的一类故障；明说了他反而能接受。

**第 3 级多命中时**取与原 `offset` 最接近的那一处（用全局字符进度比距离），不是取第一个。

**指纹的搜索成本**要单独提一句：它是 `O(章长)` 的一次子串匹配。批量恢复一本书的几百条批注时，
这件事必须走后台作业，不许在渲染路径里逐条做（`plans/阅读管线.md` 第十节的归属表里"批注回显的 relocate"
那一格就是它）。

## 五、原文快照的双重身份

`quote` 一个字段解决两个需求，这是它值得存在的理由：

- **给人看**：笔记列表那一屏要显示"她抱着铁锅站在门口……"，而列表里那本书根本没打开、没排版，
  矩形与偏移都算不出来。
- **给机器找**：锚失效时靠它搜索重定位。

拆成两个字段会得到两份可能不一致的真相；合成一个字段则**显示与重定位用的是同一串字**，
不会出现"列表里显示的和实际跳到的不是同一处"。

长度策略：起止各若干字（够唯一即可，不是整句）。太长会撑大库并让搜索变慢，太短在高重复句式
（网文的"XX道"）里会多命中。

## 六、版本戳：迁移，不是冻结

偏移口径一变，全库历史位置集体平移且**不报错**——那是最贵的一类 bug。所以每行位置自带版本戳。

**不需要新建机制**：库里有 `books.index_version`（`store/schema.rs` 的 v9 迁移加的那列，注释原话是
"分章规则或位置方案一改（比如 Markdown 的标题层级），老库里那些 `Section(n)` 就指到别的章去了"）。
本文沿用它，并把覆盖范围从"分章规则"明确扩到"文本规范化口径"。

会触发升版的具体例子（不是抽象风险）：**行内图片在文字流里占不占一个字符位**。占位是必要的，
否则"这张图和这段字在第 3 行"这类偏移无法表达；而哪天决定不占位，每张图之后的所有偏移集体平移，
没有任何报错，只是高亮安静地画错位置。

读到旧版本的行时的处置：**做迁移，不冻结旧算法**。

```
旧版本行 → 用 quote 在新口径下重定位 → 改写这四个字段 → 版本戳升到当前 → 报告置信度
```

对照一条别人的做法：KOReader 把解析器的 DOM 规范化版本随位置一起存（`cre_dom_version`），
并且为了旧位置可解析**永久冻结旧规范化行为**——它那么干是因为它有二十年存量批注要护。
本项目不抄这条：单人项目永久保留旧规范化路径很贵，而存量批注为零，走一次性迁移更划算。
**该抄的是"版本戳是数据的一部分"这个原则，不是它的兼容策略。**

## 七、章身份：`source_key` 各格式取什么

分工已定（`plans/导入管线.md` 已决第 10 条）：**提供方交 `source_key`，永久章 ID 由库的映射表分配。**
本文把各格式的取值定下来：

| 格式 | `source_key` 取值 | 为什么稳 |
|---|---|---|
| EPUB / 单 XHTML / FB2（条目式） | 该章正文资源在**资源表里的归一化 href** | 归一化后是容器内绝对路径，重排 manifest 不改它 |
| `.fb2.zip` / 内嵌分章 | `归一化href + "#" + section id` | FB2 的 `<section id>` 是书里自带的手柄 |
| Markdown（按标题分章） | `"md:" + 该标题的归一化文本 + ":" + 层级路径` | 内容寻址：标题不动，章身份就不动 |
| TXT（按块数合成章） | `"auto:" + 首块前若干字的哈希` | 纯下标不稳，掺内容才稳 |
| CBZ / CB7 / CBR / CBT / PDF / AZW4 / DjVu（定版式） | `"page:" + 页序号` | 页是既定的，下标即身份。这一族**已落地**：`LocatorKind::Page` 那条口径下 `Locator.chapter` 就是页号、`offset` 恒 0 |

三条配套规则：

1. **`source_key` 不许直接当落库的锚用。** 它是提供方的词汇，会随解析器改版而变化；
   `Locator.chapter` 存的是库分配的永久 ID。中间那张映射表就是为了让锚与解析器解耦。
2. **映射表要能重放**：`(book_id, source_key → chapter_id)` 是导入产物，可整表重建；重建时按
   `source_key` 找回旧 ID，找不到的（`md:` / `auto:` 那类内容寻址改了内容）走一次 quote 重定位。
3. **纯下标一律禁止**。书换版本、章被合并、分章规则一改，下标就指向别的内容，而这是**静默错误**。
   今天锚里若已有 `Section(n)` 这种下标形态，它正是本文要改掉的东西。

## 八、序列化文本形式

一个位置要能写进库、进日志、被将来的同步协议原样传给另一台设备，所以它需要一个文本形式。
四条规则：

1. **自描述带版本**：版本戳是串的一部分，不是外部列（外部列管库内查询，串本身要能离开库活）。
2. **可解析失败**：坏串解析成 `Err`，不许退化成"章 0"。截断的同步数据静默变成"跳回书首"很难查。
3. **稳定可比较**：同一位置的串必须逐字节相同（字段顺序固定、数字不带符号前导零），
   否则"相同位置"要去比对象而不是比串，同步时无法廉价判重。
4. **不要塞进 URL**：它是坐标不是资源。要能被设备之间当作不透明键存储。

同时保留一个**二进制/结构化表示**（写库用列，同步用文本），两者只在一处转换，别处不手写串。

## 九、定版式那一支：留位，不实现

`Locator` 要能同时表达两套参照系，否则将来做 PDF 时要改的是格式而不是加一个变体：

```rust
pub enum Locator {
    Flow { chapter: ChapterId, offset: u32, mark: Option<StructuralMark>,
           quote: String, format_rev: u32 },
    /// 第一版**只留类型，不实现**：页 + 页内坐标，原点是该页左上角
    FixedPage { page: u32, x: f32, y: f32, format_rev: u32 },
}
```

**唯一允许的分岔在几何换算那一步**（`y_of` / `hit` / `rects`），其余代码——批注表、进度、
排序、导出、同步——只处理一个 `Locator`，不许出现 `match` 两个变体的分支。

比较规则也要在定版式那支定下来：`(页, 页内推进量)` 的字典序。双页模式下"左右哪页在前"必须写成一个约定，
不能靠现场判断（那正是会漂的地方）。

## 十、表结构

三类数据形状不同，别塞成一张表：

| 表 | 形状 | 内容 |
|---|---|---|
| `positions` | **每本书一行** | 现在读到哪：一个 `Locator` + 更新时间 |
| `annotations` | 每本多行 | 一条批注 = 两个 `Locator`（起止）+ 类型 + 颜色 + 备注 + 时间；矩形不落库，从锚重算 |
| `read_chapters` | 每本多行 | 到过哪些章 |

`read_chapters` 之所以独立存在，是因为 `positions` 每本书只有一行——它记"现在在哪儿"，
答不了"到过哪些地方"（这是 `store/schema.rs` v10 那次迁移加它的原话）。

两条附加规则：

- **高亮不许跨章**（已决）。允许存就要在笔记列表里显示成一条看不懂的条目；章是读者直觉里的
  "一次阅读"。数据结构上合法但 UI 禁止，判定点放在选区形成那一刻。
- **跨页高亮不用特殊处理**：两个锚同在一章内就天然合法，矩形每次重算。

## 十一、命名收口

现在有三个名字在讲相邻的两件事（都从 `folio_core` 公开导出）：

| 现有名字 | 它实际是什么 | 本文的归属 |
|---|---|---|
| `position::Locator` | 阅读位置（章 + 偏移） | **保留这个名字**，指内容坐标本身 |
| `anchor::TextAnchor` | 一段文本范围的锚点（起止） | 保留：它是**两个 Locator 加上 quote 的组合**，批注的单位 |
| `anchor::Confidence` / `Relocated` | 重定位的结果与可信度 | 保留：第四级降级的返回类型 |
| `format::ChapterLocator` | 章的**内容**在容器里怎么取（资源寻址） | **该改名**：它是 `Address` / `ResourceRef` 一族的成员，和阅读位置毫无关系 |

规则一句话：**`Locator` 这个词只指"读者的位置"；"内容在哪儿"一律用 `Address` / `ResourceRef` 一族。**
`format::ChapterLocator` 与 `position::Locator` 撞的是同一个词，而它们分属两套坐标系——
这套东西一旦混用，写出来的代码会看着合理而实际指错地方，这类 bug 编译器与测试都拦不住。
改名放在 `Locator` 落地的同一轮做，一次性搜替，不留兼容别名（留着两个名字才真的会混）。

## 十三、测试门

每条都应当在功能未实现时失败：

- **改字号 / 换窗口宽 / 转屏** → 重开书后每条批注的锚仍落在**同一句**上（断言 quote 匹配，不断言像素）。
- **合并两章** → 第四级降级链依次命中：段锚失败 → quote 成功 → 置信度报"近似"。
- **删掉一段并保留原文** → 批注靠 quote 回来，多命中时取离原全局进度最近的一处。
- **原文被改写、quote 也搜不到** → 报"位置丢失"，落章首，**不许静默放到别处**。
- **`quote` 与锚不一致**（手改库） → 以锚为准，并产生一条诊断记录；两者互为校验而不是互相覆盖。
- **两个 `Locator` 比较与相减** → 字典序全序成立；跨章相减走章字数表，结果与视口宽度无关。
- **序列化可逆** → 串→对象→串逐字节相同；坏串返回 `Err`。
- **同一本书两台设备**（屏幕宽度差一倍） → 显示同一个百分比、跳到同一句。
- **`reindex` 后重放映射表** → 章 ID 不变、历史批注一条都不漂。
- **版本戳升一版后打开旧库** → 触发一次迁移作业、`format_rev` 被改写、置信度可见。
