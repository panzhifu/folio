# Folio 软件架构

本文描述 Folio 当前的整体结构：crate 划分、依赖方向、内部分区、关键数据流与
横切机制。以代码为准，改了架构顺手改这一篇。

## 1. 概述

Folio 是 Rust 写的原生 GPU 阅读器，覆盖桌面（Linux / macOS / Windows）与移动端
（Android 打包发布，另有 iOS 与 HarmonyOS 两条入口臂）。两条根本的架构决策：

- **不嵌 WebView，不引浏览器引擎。** 正文由自研排版引擎产出：DOM → CSS 子集
  → 排版 → 绘制。排版自己做，才有条件做书的那套版式——首行缩进、居中章标题、
  混排 run、图片守 `width` / `max-width`、脚注、竖排。
- **引擎与界面分离。** `folio-core` 零 GPUI 依赖是硬边界：排版、锚点、SQLite、
  配置都能在没有任何窗口的情况下跑，也才能被 `cargo test` 全量覆盖。

在这两条之上，其余的形状都由依赖图强制，而不是靠约定自觉。

## 2. Workspace 总览

```
crates/
  folio-base/    地基：时间、路径、作业池、取消、日志、身份、内存预算
  folio-model/   公共数据模型：诸 crate 共用的类型，只有数据
  folio-format/  文件格式解析：字节 + 路径 → 统一文档模型
  folio-net/     出网地层：传输抽象（Transport / RemoteStore / Sink）与 WebDAV
  folio-ai/      AI 问答与选区翻译：一层 provider 与三只翻译引擎
  folio-render/  排版引擎：DOM + 样式 → 扁平的块盒 / 行盒两张表
  folio-core/    引擎：内容与锚点、书库（SQLite）、导入、剩余的网络面
  folio-app/     应用壳：GPUI 界面、平台入口、原生桥
tests/           fixtures（程序合成的书可入库；真书只放 tests/fixtures/local/ 且不入库）
packaging/       四端安装包里的非代码资产（图标、desktop 条目）与打包脚本
reference/       借鉴用的上游只读克隆（含 AGPL），gitignore，永不入库、不参与构建
```

crate 依赖图（箭头 = 依赖）：

```
folio-app ──▶ folio-core ──▶ folio-format ──▶ folio-model
                │  │  └─▶ folio-render ──▶ folio-format
                │  └─▶ folio-ai ──▶ folio-net ──▶ folio-base
                └─▶ folio-base

folio-base / folio-model  零依赖（连业务类型都不认识）
```

要点：

- **应用壳只直接依赖 `folio-core`。** `folio-model` 的类型与 `folio-format` 的
  扩展 trait 经 `folio-core` 的 re-export 沿用旧路径（`folio_core::position::*`、
  `folio_core::store::*`…），app 不必知道类型住在哪一层。
- **拆 crate 照「换 crate 不换形状」**：模块搬进新 crate 后，core 经别名沿用旧路径
  （`pub use folio_render as layout;`、`pub use folio_net as remote;`、ai/translate
  经 shim），所有消费方一行不改；行为上的唯一适配是「配置 → 参数」的映射收在
  core 的入口层（`net::ai::configured` / `net::translate::configured`）。
- 每条边界都靠依赖图强制，多数还配了测试：`folio-model` 有 boundary test
  逐行扫自己的 Cargo.toml；core 的契约测试钉住「引擎不认识格式」「Reader 全字段进键」。

## 3. 各 crate 的职责与边界

### folio-base —— 地基

不解决任何业务问题，但每条业务线都要用。往里加东西前先问：它与「一本书」
有没有关系？不依赖 `folio-format` / `folio-core`。

| 模块 | 职责 |
|---|---|
| `budget` | 内存预算与降级顺序（`MemoryBudget` / `Pressure` / `EvictStep`） |
| `cancel` | 协作式取消标志，作业与网络共用 |
| `error` | 地层错误：读盘与日志装配 |
| `identity` | 内容寻址：字节 → SHA-256 身份 → 书库副本文件名 |
| `logging` | `tracing` subscriber 的装配与轮转 |
| `paths` | **唯一的路径来源**：配置根、数据根、书库各区 |
| `task` | 后台作业管线：可取消、可报进度、四档优先级 |
| `time` | 日历换算：Unix 秒 ↔ 本地日 ↔ `YYYY-MM-DD` |
| `usage` | 磁盘占用按去处分类数一遍 |

### folio-model —— 公共词汇表

诸 crate 里唯一「只有数据」的一层：格式解析（产）、排版引擎（排）与书库（存）
共用同一套词汇，谁都不必为了几个类型依赖另一家的实现。新东西进来先过三问：

1. **只有数据**：struct / enum + serde 派生与纯算术方法，零 I/O、零解析、零排版。
   行为留在消费它的 crate（锚点重定位在 folio-core，`copy_extension` 在
   folio-format——都是扩展 trait）。
2. **两个以上 crate 要用才进来**，只用一个的留在原 crate。
3. **换 crate 不换形状**：serde 表示逐字节稳定，库里的载荷不做迁移。

| 模块 | 内容 |
|---|---|
| `anchor` | 锚点：坐标 + 找回坐标的文本指纹（重定位算法在 folio-core） |
| `char_class` | 词 / 空白 / 换行分类，划词吸附共用 |
| `content` | 内容两族：可重排 `FlowDoc` 与定版式 `FixedDoc` |
| `format` | 章表与书目：`Format` / `Chapter` / `DocMeta` |
| `novel` | `.txt` 分章规则的读者差量（出厂表与引擎在 folio-format） |
| `position` | 阅读位置 `Locator`：存章内字符偏移，不认页码 |
| `reading` | 阅读偏好的档位词汇（如图往哪块尺寸折） |
| `types` | 书库记录的行形状（批注 / 书签 / 集合 / 统计） |

### folio-format —— 格式解析

只回答「这份文件是什么、怎么把它读成章表与正文」：**字节 + 路径 → 统一的
文档模型**。21 个 provider、33 个扩展名，覆盖 EPUB / MOBI / PDF / DjVu / 漫画包
（CBZ·CB7·CBR·CBT）/ CHM / Word（.doc·.docx）/ ODT / RTF / FB2 / HTML 族 /
Markdown / 纯文本等。不认识数据库、网络、界面与读者偏好；需要落盘目录的地方
由调用方注入。判定的规则是「后端解析能脱离 app 单独用」。

- `provider` —— 注册表与判定：`provider_for` / `sniff` / `ParseBudget`。
- `container` / `zip` / `archive` / `palmdb` —— 各族容器层。
- `dom`（html5ever arena DOM）、`css`（CSS 子集求值）、`scan`（一趟 tokenizer
  出章摘要与字符坐标）。
- `charset` / `char_class` / `href` / `metrics` / `woff`·`woff2` / `svg` —— 共用件。
- `ext` —— 搬进 folio-model 的类型上与解析绑定的行为
  （`Chapter::inline` / `copy_extension` / `PageText::text_map`）。

### folio-net —— 出网地层

传输抽象与 WebDAV 协议（原 folio-core::net::remote）。这一层只认识「把请求发出去、
把响应拿回来」，不认识书库与配置 —— 消费方各自把参数递进来。自带 `Error` / `Result`
（凭据永不进 `Debug` / 日志，`redact_url` 一处收口）。

- `Transport` —— 唯一出网原语：`request`（整个进内存）与 `download`（流式 +
  `Sink` 落地策略 + 块间取消）。**同步签名是有意的**：管线的作业跑在后台线程上。
- `RemoteStore` —— 远端仓库五动作（列 / 读 / 写 / mkdir / 流式下载）。
- `dav` —— WebDAV 协议的规则层（路径转义、`Depth`、207 多状态），离线可测。
- `ureq` —— 同步实现（rustls + 打包根证书，Android 上没有 `/etc/ssl` 可靠）。
- `dav::Mock`（`test-support` feature）—— 假传输，folio-net 自己与 core 的网盘
  / 传书测试共用。

### folio-ai —— AI 问答与选区翻译

「同一件事的两张脸」住一个 crate（原 net::ai / net::translate）：都是「把一段书本文
交给一个外部模型，拿回一段文字」，共享传输、语言名表与错误分档的纪律。

- `ai` —— OpenAI 兼容的一层 provider（`chat/completions`）、三档预设问法
  （`Ask::Explain` / `Terms` / `Plain`）、切章规则草案的提示词、三个尺寸闸
  （输入 12k / 选区上下文各 300 / 答案 4k）。
- `translate` —— `Translator` trait + 三只引擎（Google 免 key、OpenAI 兼容、DeepL），
  译文缓存键 `source_hash`。
- **只收纯字段**：本 crate 不认识配置文件。配置到参数的映射与「这一格存不存在」的
  None 判据（没开 / 地址空 / 没填 key 不出网）在 core 的入口层
  （`net::ai::configured` / `net::translate::configured`）。
- 日志纪律两条链同守：正文与答案都不进日志。

### folio-render —— 排版引擎

DOM + 样式 → 扁平的块盒 / 行盒两张表（原 folio-core::layout）。零 GPUI 依赖的硬边界
在这里延续；断行取自 UAX #14（中文禁则），字体只提供两种度量能力。分页要按高度切
行盒，所以输出是**扁平表**而不是树，父子关系按行盒包含关系还原。

- 排版三步：`collect`（行内子树展平成文本 + piece 表）→ `wrap`（断行）→
  `children`（块级摆放）；`fragment` 按可视高度切片、`page` 分页。
- 失效键（`LayoutKey` / `LayoutInputs`）一处构造、各级缓存共用；**对偏好只要求
  `Serialize`** —— 「整份哈希、加字段自动进键」的纪律原样成立，字段表钉子在
  core 的契约测试。
- 对配置的耦合为零：本 crate 不认识配置文件——core 把整份 `config::Reader` 直接递
  进来（它是 serde derive 的，`LayoutInputs` 以泛型 `Serialize` 收下）。

### folio-core —— 引擎

书本模型、标注锚点与存储层。内部按「谁依赖谁」分区，方向单向：
`content` 可以依赖 `infra`，但不依赖 `store` / `ingest`；`infra` 谁都不依赖。
这条方向是「引擎能在没有数据库的情况下跑」与「core 能被全量测试」的前提。
（排版、传输层与 AI/翻译已独立成 folio-render / folio-net / folio-ai，旧路径沿用。）

| 分区 | 职责 |
|---|---|
| `content` | 内容与文档：统一 `Document` trait（可重排 / 定版式）、锚点与四级降级重定位、命中查询、批注读侧、封面资产、解析产物校验 |
| `store` | SQLite：书目、进度、批注、书签、集合、统计、导入日志、同步游标 |
| `ingest` | 书怎么进来：导入管线、扫描、文件夹监听 |
| `net` | 剩余的网络面：WebDAV / 云盘、OPDS、Wi-Fi 传书、局域网同步、更新检查、会员兑换（传输抽象与 AI/翻译在 folio-net / folio-ai） |
| `infra` | 横切：配置、i18n、日志、书内设置、诊断 |

分区之外的顶层模块：`reader`（阅读会话：开书、几何、翻页）、`search`（书内全文
检索）、`speech`（朗读引擎接口与事件）、`dict`（词典库）、`text` / `fonts`
（字体族扫描与装载）、`cache`（缓存策略）、`account` / `backup` / `sync` /
`group`（书架分组）、`services`（服务组合根）、`error`（`thiserror` 枚举，每个
变体自带上下文、底层原因留在 `Error::source` 上）。

i18n 也在这层：`locales/` 一门语言一份 TOML，编译期嵌入，fallback 为英文。

### folio-app —— 应用壳

唯一的 GPUI 依赖方。桌面是 `bin`；`crate-type` 同时列 `rlib` / `cdylib` /
`staticlib`——Android 与鸿蒙宿主 dlopen 的是 cdylib，iOS 由 Xcode 链接 staticlib。
视图统一 `use gpui_kit::…`（gpui-kit 顶层把移动端那份 `gpui-pre` 整个转出），
不直接引 `gpui`。

`src/ui/` 下的依赖方向只有一条：

```
shell ▶ features ▶ components ▶ services ▶ foundation
              ▲                    ▲
           host ──────────────────┘（平台服务边界）
        platform（四臂入口与原生桥）
```

- `foundation` —— 主题、文案、错误约定、图片索引、颜色换算。无业务、无 IO。
- `services` —— 有生命周期、无元素树：配置、书库连接、导入队列、监听、传书、
  云盘授权、词典、更新。
- `components` —— 跨纵切复用的组件：顶栏、搜索框、底部弹层、字体 / 主题选择器。
- `features` —— 按能力纵切，每个功能自带 model / view / components / overlay：
  `reader` / `shelf` / `notes` / `stats` / `settings` / `welcome` / `cloud` / `opds`。
- `shell` —— 自适应导航：宽屏侧栏、窄屏底栏、折叠态，每个目的地一个导航栈。
- `host` —— 平台服务边界：安全区、输入法、正文字体、本地时区偏移。
- `platform` —— 四臂入口：`desktop` / `android` / `ios` / `ohos`，外加系统字体
  探测与用户字体装载。

一条硬规矩：**`cfg(mobile)` 只允许出现在 `host` 与 `platform`**。两端共用同一份
逐字形阅读渲染，平台之间只剩「导航栏占的是宽还是高」这类数据差别，走参数传入。

## 4. 关键数据流

### 4.1 从字节到像素

```
文件字节
  │  sniff + provider_for（folio-format 判定）
  ▼
provider 解析（21 个，各归各的容器层）
  │  产出 FlowDoc（可重排）或 FixedDoc（定版式）—— 类型在 folio-model
  ▼
DOM + CSS 子集求值（StyledDom）
  ▼
排版（folio-render）
  │  collect → wrap → children ⇒ 扁平的 BlockBox / LineBox 两张表
  │  fragment 分片 · page 分页 · 失效键 + 两级缓存
  ▼
GPUI 绘制（gpui-kit 组件 + 逐字形绘制）
```

排版引擎刻意做成扁平表而不是树：分页要按高度切行盒，树形碍事，需要父子关系时
按行盒的包含关系还原。三步分工：

1. **收集**（`collect`）：把行内子树展平成文本 + piece 表，每个 piece 带自己
   元素的计算样式，`<em>` 的斜体、`<small>` 的小字不会丢。
2. **断行**（`wrap`）：引擎自持，断点取自 UAX #14——中文禁则（标点不落行首 /
   行尾）的依据；字体只提供单字前进量与整段绘制度量两种能力。
3. **摆放**（`children`）：块级顺序、兄弟外边距折叠、`text-indent`、`text-align`。

定版式一族（PDF / DjVu / 漫画包 / AZW4）不走排版：页是既定的画布，字节栅格化
出像素，走逐页模式（缩放、分享、保存）。

### 4.2 阅读位置与锚点

- **位置是章内字符偏移**（`folio_model::position::Locator`），不是页码——字体
  大小、窗口尺寸、重排都不会让位置失效。
- **锚点**（`TextMap` / `TextAnchor`）：可见文本坐标系 + 文本指纹，批注与高亮
  挂在锚点上；文档变化后按四级降级重定位（`folio-core::content::anchor`）。
- 可重排与定版式共用同一套锚点系统。

### 4.3 书的进出

导入管线（`ingest`）：来源（文件 / 文件夹监听 / 云盘 / URL / OPDS）→ 身份
（SHA-256 内容寻址，`folio-base::identity`）→ 书库副本 → 章表与书目入 SQLite →
封面缩略图落资产区。删除书时连着带走解压产物那一格缓存（如漫画包）。

## 5. 横切机制

| 机制 | 位置 | 说明 |
|---|---|---|
| 内存预算 | `folio-base::budget` | 全局预算与降级顺序（`EvictStep`），图集、缓存按压力逐档收缩 |
| 后台作业 | `folio-base::task` | `TaskManager`：可取消、可报进度、四档优先级；事件经异步通道搬回界面线程 |
| 取消 | `folio-base::cancel` | 协作式取消标志，作业与网络共用 |
| 路径 | `folio-base::paths` | 唯一路径来源；格式层不自己找目录，由调用方注入 |
| 时间 | `folio-base::time` | 日历换算；core 的时区一律是参数（零进程环境依赖），「读者在哪个时区」由 app 侧回答 |
| 错误 | `folio-core::error` / UI | core 是 `thiserror` 枚举（因果链在 `source`）；界面侧收成 `anyhow`，`{err:#}` 一路到底 |
| 日志 | `folio-base::logging` | `tracing` 装配与轮转；Android 落 logcat、鸿蒙落 hilog |
| i18n | `folio-core::locales` | 一门语言一份 TOML，编译期嵌入，9 门语言，fallback 英文 |
| 配置 | `folio-core::infra::config` | 版本化的 `Config` 与 `Resolved`；书内另有一层 `book_settings` |

## 6. 平台矩阵与第三方快照

| 平台 | 形态 | 入口 |
|---|---|---|
| Linux / macOS / Windows | `bin`（`folio`） | `platform::desktop` |
| Android | cdylib + Gradle 工程（`crates/folio-app/android`） | `platform::android`（JNI 桥） |
| HarmonyOS | cdylib + ArkTS 宿主（`crates/folio-app/ohos`） | `platform::ohos`（napi 桥） |
| iOS | staticlib，由 Xcode 链接 | `platform::ios` |

GPUI 那一棵依赖树按「快照整体走」的规矩钉死，任何一格跳版本都要一起跳：

- `gpui-kit` 走 git main（主题目录只存在于源码树，发布 crate 不带），锁记录 commit。
- 移动端宿主是 `gpui-pre-mobile`，钉 rev；桌面端不编译它。
- `gpui-pre =0.3.11` 是整套快照：渲染器三件（`gpui-pre` / `gpui-pre-wgpu` /
  `gpui-pre-platform`）patch 到 `panzhifu/gpui-folio`（仿真翻页的 Mesh primitive、
  网格管线与圆柱受光在那边），纯 CPU 的顶点与 uniform 定义在 `folio-curl`
  （folio-app 直接引它）。几处 rev 必须是同一个数，否则两棵 `gpui` 的
  `Window` / `Scene` 类型对不上，编译直接炸。
- HTTP 栈不另起一棵树：`reqwest_client` 实为 `gpui-pre-reqwest-client
  =0.3.11`，给 gpui 依赖图里已在编译的 reqwest 补一个 `HttpClient` 实现。

## 7. 拆分路线图（任务清单）

folio-core 按功能区继续拆成独立 crate。每步照同一条纪律：**换 crate 不换形状**——
模块搬进新 crate，core 经别名沿用旧路径，消费方一行不改；行为适配只有「配置 → 参数」
一种，收在 core 的入口层。

- ✅ **阶段一（本轮已完成）**：`folio-net` 种子（remote 传输层 + WebDAV）、
  `folio-render`（排版）、`folio-ai`（AI + 翻译同 crate）。
  唯一的行为适配：`LayoutInputs` 对偏好改为泛型 `Serialize`（`config::Reader`
  直接满足）；AI/翻译的 `configured()` 留在 core 做配置挑选。
- **阶段二：sync 纯数据类型剥离。** `Snapshot` / `BookEntry` / 各记录类型 /
  `TombstoneKind` 下沉 folio-model（serde 数据，两个以上消费方）。
  卡点：`sync.rs` 与 store/net 的双向环（sync→store::Store、store/sync→sync；
  sync→net::remote、net/lansync→sync）——剥完才谈得上 net 扩容与 store 拆出。
- **阶段三：folio-net 扩容。** cloud / opds / transfer / lansync / update / redeem
  搬入；`UploadBook` 类型归 folio-model；`account`（ring 唯一用户）独立
  folio-account。卡点：config 的 Cloud/Ai 节——照 folio-ai 的入口层适配即可。
- **阶段四：folio-store。** store 搬出、自带 Sql 错误；`group.rs` 是纯 model
  函数，顺路并入 folio-model。卡点：`book_settings → config::{Reader, Appearance}`。
- **阶段五（可选小拆分）**：speech / dict / search / text / fonts / cache 各自独立
  ——全部零消费者、依赖闭包干净（speech 还带 tts 的平台门控依赖同迁）；
  `error.rs` 逐 crate 自持，core 留伞枚举收编。
- 顺手清理项：core 的 `dirs` 死依赖已删；`engine_input_contract` 的扫描路径
  已随 folio-render 更新。

## 8. 测试与仓库约定

- 测试内联在被测文件底部，点名导入（不用 `use super::*`），只引 `pub` 项；
  `gpui_kit` 根的 `test` 属性宏把 `#[test]` 递归展开成它。
- 日常跑 `cargo test --workspace --lib`；CI 同款 `cargo test --workspace` 买的是
  「每个 target 都编得过」。
- fixtures：程序合成的书可入库；真书只放 `tests/fixtures/local/` 且不入库。
- `reference/` 里的上游克隆（含 AGPL）永不入库、不参与构建。
- 版本控制是 jj / git colocated：改动经 jj 快照进当前 change，推送用
  `jj bookmark move` + `jj git push`。
