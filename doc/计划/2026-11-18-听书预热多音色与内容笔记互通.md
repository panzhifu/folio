## 2. 已核实问题：导入与内容修改

普通新导入的真实流程是：外部文件→分块复制到`.staging`→完整SHA-256→格式识别/判重/解析→发布哈希名副本→登记书目、章表和资产。**新导入不会改名或改写外部原件**；变化的是书库中的副本名。移动选择器的临时副本按来源所有权清理，历史库中“当前书库内、无哈希的旧文件”另有改名补齐流程。

代码依据：`folio-core/src/ingest/import/sources.rs:33,126`、`pipeline.rs:734,773,938,965,999,1205`、`maintenance.rs:244`；路径均相对`crates/`。

本次用正式编译产物、临时Markdown和临时SQLite进行探针，未读取真实用户书库。原文与结果在本机已忽略的`target/import-investigation/probe.rs`、`results.txt`；实施时需把最小案例转成仓库必跑回归。

| 操作 | 已复现结果 | 需要解决的语义 |
| --- | --- | --- |
| 初次导入 | 原件名字/字节不变；生成16位哈希名副本 | 界面解释原件与托管副本的区别，保留来源信息 |
| 编辑外部原件，再导入 | 新增另一个book_id，旧批注留在旧书 | 用户应能选择更新既有书，不能只得到重复书目 |

| 上一步后重导旧字节 | **Windows已复现覆盖编辑后的副本** | P0：发布目标存在时不能无条件rename覆盖 |
| 手工改托管副本名 | 原记录Missing；重导可按旧身份自愈，改名那份仍在 | 提供重新关联，不能把缺失自动当删除 |

当前缺少持久原件路径关联；导入日志仅保留文件名且有数量上限。变化检测最终只比秒级mtime，虽然读了size却没有参与判断（`folio-store/src/books.rs:1132,1154`）。判重后仅判断旧路径存在，不复核实际字节身份。

开书发现变化只安排后台重扫，本次仍载入旧章表与当前文件，新索引下一次打开才生效（`reader/model/session.rs:1074,1094,1140,1248`）。`BookDocument`容器与全文缓存、章节异步请求均假设会话内内容不变。封面按book_id缓存，缺少统一内容修订事件；“没有新封面”还需区分确实删除与提取失败。

## 3. 导入与内容更新方案（已重新设计）

用户已确认：修改原文件，Folio自动识别更新；后台准备新版，阅读中提示切换，未打开时自动采用。原I0–I3的“托管副本＋主要靠手动更新”路线由[导入与原件自动更新重设计](2026-11-18-导入与原件自动更新重设计.md)替代，以该专项计划的A–E验收包为准。

新的主模型为Book（稳定身份）、Source（本机原件关联）、Revision（固定阅读版本）。同源保存不会新增书卡；内容哈希只认字节，原件与副本保留可读名字。首次导入、自动更新、重新关联和手动补救复用一条捕获/校验/发布管线，采用前检查来源代数、当前版本和活动阅读会话。

原始笔记锚点留在建锚版本，新版位置是派生映射。v1同步在准确内容版本桶中持续工作：旧uid不改锚点后移到新hash，旧进度不覆盖新版进度，删除墓碑回原桶。自动更新启用前即完成该兼容桥；跨设备自动传播逻辑书的版本关系另需后续协议，不能把长期暂停同步当交付。

修订模型是后文CFI交换的前置。内部关联原件的受控更新可以生成可靠的重定位显示映射；外部笔记导入无法证明同版时仍按第5节预览确认，两个场景不混用授权。

## 4. 听书初始化与多音色

### 实施前核实事实（2026-11-18）

- 当前点击听书才经`arm_speech`调用进程单例，在线程内执行`Tts::default()`；Android需冷绑定系统服务。后端每次等500ms，Folio做4次尝试、间隔900ms，等待预算可达约4.7秒，另有系统构造/调度/首句合成成本。这不是本次手机实测值。
- `Config::Speech`只有rate/pitch/auto_scroll；Engine没有声音目录与选择接口。调音高不能替代切换发音人。
- `tts 0.26.3` Android后端voice能力未实现；Linux的Speech Dispatcher已有列声音/选声音，但Folio没有暴露。Windows/macOS/OHOS目前未启用听书后端，不在本期假称全平台都能朗读。
- 上游Android存在创建实例后才登记pending的早回调竞态、失败状态不充分区分、超时/析构缺少shutdown等问题。只增大500ms超时不构成完整修复。

代码依据：`folio-speech/src/lib.rs:69,133,144,284,331,389,418`、`folio-core/src/infra/config/speech.rs:6`、`reader/model/speech.rs:72,123`。

### S0：可靠生命周期与首帧后无声预热

推荐保留现有Engine/Command/Event外观和Linux后端，为Android做小型原生异步适配器；先核对维护成本，如选择修补tts依赖也只改Android机制并固定来源，不搬入Tauri应用层。

- 平台/JNI、恢复根和现有功能资格就绪后，首帧呈现后的空闲任务启动单实例准备；UI线程不等待它，不读取书文、不发送Speak、不申请音频焦点或发朗读通知。
- 初始化中/Ready/Failed/Timeout明确区分；一次在途、generation隔离早到/迟到回调，失败/超时释放旧实例，重试不叠加服务绑定；退出时stop/shutdown。
- 后台预热失败不阻断阅读，用户打开听书可看到状态并重试。不能承诺用户立刻进听书时绝对零等待，也不能把绑定完成当作首句音频已经合成。
- 播放事件仍由当前阅读会话独占消费。`Engine.events()`是竞争通道而非广播，预热/设置页不得另起消费者吞Ready/Done；目录查询用独立请求响应或持久快照。

### S1：系统声音目录与本机偏好

- 声音模型包含后端、引擎作用域、原始voice ID、显示名、完整BCP47、联网要求、安装状态、可选质量/延迟；未知信息标Unknown，不能保存列表序号或仅显示名。
- Android接公开getVoices/setVoice，区分已安装本地、需下载、需联网和未知。`setVoice/setLanguage`可能触发数据下载，**枚举和预热不能逐声音试设**；默认只自动选已安装本地候选，不自动联网/下载。
- 公开API无法可靠确认实际绑定引擎时报告能力边界，不用隐藏getCurrentEngine，也不把默认包名冒充实际绑定包名。
- Linux第一期只列当前模块；现tts封装未暴露模块，需最小后端扩展以查询/锁定明确模块，才能可靠保存(module,name)。拿不到模块时标Unknown且重新验证默认模块变化后的选择，不能宣称ID跨模块稳定；以后列多模块也避免同名冲突。
- 配置追加可选本机声音选择和语言偏好，缺省为系统默认，旧语速/音高/跟读保持；恢复/迁移/serde往返有用例，声音ID不默认跨设备同步。
- 语言回退：用户选择→完整语言/地区→主语言→系统默认；保留script/region，不用截前两字符。所有自动回退仍受已安装本地策略约束，系统默认若需联网/下载也不能自动选，改为提示并等待用户显式选择。声音消失时保留原偏好并提示临时回退，不静默永久改配置；无可用声音时停止并解释。
- 设置页与听书页共用目录服务，services不调用reader。用户选择成功后才显示生效；播放中切换先停在当前句，不自动朗读或跳句，清零该声音的字/秒速率估计。
- 当前Android错误归Done会推进、同步调用错误只日志；多音色同时补错误事件与“留在当前句”语义。

### Tauri 2 与 Readest 能借鉴什么

Tauri的setup不是自动异步：官方移动插件文档说明Android原生命令在主线程，耗时工作仍需显式调度。可借“注册→异步准备→Ready→生命周期清理”，无需让Folio迁移框架。

Readest原生Android实现用异步onInit，支持声音目录/选择与shutdown；NativeTTSClient有8秒前端等待预算，控制器各引擎有15秒预算。Promise.race超时不会自动取消原生初始化或释放实例，不能作为完整清理实现照搬。其Native preload直接返回`Dummy preload finished`，并非系统音频预热，未发现应用启动即预热的证据。偏好按引擎+语言保存可借鉴；截两字符语言码、并行初始化所有云引擎不照搬。

验收：假后端覆盖并发单实例、零朗读预热、ERROR/Timeout/清理/重试、旧代回调、音色重名/卸载/语言回退/安装筛选/旧配置；真实GPUI控件覆盖加载、无候选、选择保存、失效提示和不自动开口。测首帧、预热、onInit、Ready、播放点击、Begin时间点，冷/热p50/p95与首屏成本分别记录。Android链接和手机回调实测分别列证据；仅用户点名后查看手机。

## 5. 笔记互通与 EPUB CFI

### 当前差距和兼容边界

Folio现在的TXT/Markdown/HTML导出明确定义为人读格式（`folio-core/src/content/annotation.rs:83`），没有稳定交换ID、CFI、书版本，也没有外部笔记导入。`TextAnchor`的chapter/start/end/exact/prefix/suffix/path继续适合内部重定位，不能直接改成CFI。

CFI不是一个所有阅读器都接受的笔记文件格式。可定位互通同时需要：同一本/同修订的识别、合法定位、引文核验、具体交换格式与导入器。PDF页内批注另有坐标/文字/页面契约，本期EPUB CFI不为PDF制造假定位。

关键技术差异：

- Folio字符偏移按Rust Unicode标量计数，CFI文本偏移按UTF-16；emoji/扩展汉字必须显式转换。
- EPUB原OPF/spine会被Folio章表过滤/重排，章下标不能直接拼`/6/2n`。保留原spine项、idref、href和OPF定位信息，不能用百分比代替。
- html5ever会补结构、合并文本；当前私有DOM path也可能让inline前后文本同名，不可机械改写成CFI。需要按原出版物结构、真实子节点顺序和文本chunk映射生成/解析CFI。
- 当前href明确忽略epubcfi；按需新增专门位置解析入口，不把普通URL fragment的既有契约随意放宽。
- Book匹配需带OPF identifier、hash算法/值与revision。Folio全SHA-256与Readest抽样MD5不可直接比较，相同标题/作者仅候选。

### N0：交换模型和原文保全

保留现有内部anchor/sync v1形状，通过追加表或字段保存外部来源软件/版本、来源记录ID、源书标识、原CFI/XPointer、引文/上下文、建锚修订、原始时间与单位、导入批次/原始载荷。

Folio交换JSON显式format/version、支持记录类型、资源限额和未知字段策略；未知版本拒绝应用但保留原文件/报告。原始外部时间不直接当本地同步逻辑版本。内部uid与外部ID映射以来源命名空间+源书+来源记录ID为幂等键，缺ID才采用可解释的规范指纹；不同书同ID不能串。

### N1：纯Rust EPUB CFI桥

格式层负责CFI语法/转义/断言/OPF-spine/章节原DOM定位与UTF-16边界；core负责与TextAnchor互转、书修订核验、引文与上下文验证。实现或选库前审阅许可/维护状态，不将AGPL JavaScript直接复制或嵌进原生引擎。

同修订高亮/范围批注需CFI与引文核验，或同修订解析差异下唯一且足够上下文证据的重定位，才可自动应用。折叠书签没有范围引文，其text可能只是章名/显示片段，使用书身份、同修订和CFI可解析性验证，文本仅作提示。首期不同修订一律在预览确认，不能因搜索唯一就自动跨版挂载。重复引文、多候选、坏CFI、缺书保留为未定位/待关联；**不自动取第一处、不降到章首、不丢笔记原文**。本期不顺带改变所有既有内部anchor回放规则，外部导入使用明确的匹配等级。

### N2：首期 Readest JSON 双向交换

Readest实际定义`$format: readest-annotations`、version1、book和annotations，记录含id/type/cfi/text/style/color/note/createdAt/updatedAt等。先支持其annotation/bookmark/excerpt中有对应Folio语义的部分；全局标注、手写、notebook等不支持项在预览列出并原文保全，不能伪装成普通高亮。

导入流程：限额解析→书匹配→库锁外定位→预览精确/重定位/未定位/重复/冲突计数→确认→一次Store事务应用。批次失败整批回滚，不使半份映射与用户笔记分离。二次导入零重复、未改记录不抖版本；本地已编辑与来源更新形成明确冲突，用户删除过的记录不默认复活。

导出显式选择目标内容revision，CFI、引文、出版物身份及hash均对应那一版；不能用H0的CFI配H1的图书身份。只有在目标版已验证的位置才生成该版CFI，未定位记录保留在Folio交换格式/报告中，不伪造为可定位的Readest条目。保留来源ID映射，书hash只填写真实算法对应值，不能把Folio SHA256写成Readest hash。Markdown/HTML仍作可读分享，并可附书版本和时间；它们不宣传为能直接导回所有阅读器。

验收必须用同一自建EPUB完成Folio→Readest→Folio及Readest→Folio→Readest，核对高亮范围、书签、引文、颜色/样式映射、笔记文字、时间与重复导入。真实Readest验证与单元fixture往返分开记录。

### N3：后续适配矩阵

| 目标 | Readest已核实能力 | Folio建议顺序/验收 |
| --- | --- | --- |

## 8. 听书实施记录（2026-11-19）

已接入首帧后的会员静默预热、共享快照、独立选声确认、Android 异步初始化/超时清理、逐句回调 ID 隔离，以及本地音色/完整语言设置。Android 的公开 API 不能证明实际绑定包，身份使用 `requested:<包名>`；Linux 使用 `configured:<模块>`，所有可用回退模块均属于已知本地模块时才允许离线选择，未知状态保留，不伪装实际绑定身份。SSIP 无具体默认音色查询，Linux 的自动档需要语言候选或显式音色。

角色设置保存稳定 ID、名称、段首前缀和音色。同段后续句沿用该角色，无法匹配或角色音色失效时使用旁白；不进行 AI 身份推断，不改变原文和锚点。旁白、语言及角色修改在后端确认成功后才写配置，失败保留旧配置。合成错误和手动切换停在当前句，不再当作 Done 跳句。
