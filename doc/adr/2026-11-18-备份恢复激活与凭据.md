# 备份恢复：隔离准备、下次启动激活与凭据选择

状态：Accepted。日期：2026-11-18。

Folio 的 Store、作业池和平台宿主具有进程生命周期；阅读页、网络回调与设置可能继续写入。恢复不在运行中替换这些资源。当前选择是准备独立副本，完全退出应用后，下次启动再固定新根。

## 磁盘契约与激活

备份 ZIP 格式仍为 v1，清单、数据库和配置序列化形状保持兼容。恢复目标固定在未切换的数据根 `restores/<随机 id>/`，解包前校验路径、文件数和容量，拒绝链接、重复路径、未来配置/schema 与损坏数据库。库中书文件重定位到 `library/`，保留 book_id；配置与主题放 `preferences/`，字体和词典分别放 `fonts/` 与 `dicts/`。

`.folio-restore.json` 记录源包身份、凭据选择与 ready 状态；OS 文件锁保证同一目录不能并发恢复，进程崩溃不会留下永久占用。未完成的同包恢复可以重试；ready 后的同包重试只返回已有副本，不能覆盖副本里的新写入。改变凭据选择必须创建另一份副本。

校验并关闭恢复 Store 后，先持久化 `restore-root.required`，再原子写入未切换配置根的 `restore-root.json`。独立标记使启动指针丢失也会停止，不能静默使用旧库。两者的位置永远不随恢复根移动。平台入口在读取配置、创建日志、打开数据库、启动作业/监听/传书之前读取选择，校验 ready 副本并一次固定本进程路径。Android 先取得宿主专属根，再读取选择；环境变量依旧决定稳定启动根。配置的数据根先 canonicalize，允许系统路径别名，恢复区内部的符号链接/junction 仍拒绝。

准备期间与准备后，当前会话继续使用原根；界面明确提示“重启后切换”，备份生成后的当前编辑仍留原库，不会跟进恢复副本。桌面与 Android 可通过退出按钮走现有关闭路径，iOS/OHOS 由系统关闭重开。原库、原文件和旧恢复副本都不自动删除。

选择指针一旦写入，就代表下一次启动使用该副本。已激活副本发生损坏或配置不可读时启动失败，不能自动回滚旧选择，否则会隐藏已经写入新库的数据。人工恢复应先备份所选根，再修复副本或明确选择另一份备份；不要通过删除启动指针“修复”启动。当前不提供在线热切换或自动回滚。

## 凭据

现有备份完整保存配置密码、API key、局域网密钥和网盘 token，不在本次改变导出契约，也不声称备份已加密。恢复预览指出是否含凭据；界面“恢复密码与 API 密钥”默认关闭，只清除恢复副本中的同步/云盘/OPDS 密码、翻译/供应商 key、局域网密钥和 OAuth token。用户显式勾选时保留这些值；源包和活动配置始终不改。

两种选择都关闭恢复副本的同步、局域网账号与目录监听，生成新的同步 device_id，避免把源安装冒充成同一设备。恢复后由用户明确重新开启网络能力。密码清除不改变图书、阅读设置、批注、书签或进度。诊断仍使用安全白名单，不能记录配置或凭据。

## 验证

合成书与临时 SQLite 验证新目录恢复的书目、进度、书内设置、批注、书签，数据备份缺书保全、越界/超限拒绝、崩溃锁文件重入、ready 重试保留编辑。启动选择测试跨多个新建控制器模拟多次启动，覆盖原库继续编辑、新库编辑后再次启动、坏包保持既有选择与损坏副本拒绝回退。应用状态与真实控件测试覆盖预览、默认不恢复凭据、复选框、取消、失败和准备状态。编译/无头交互不等于四平台打包或真机验证。
