## 1. 结论

### 1.1 不要重做的三件

1. **不要重做两阶段排版、不要恢复 `LayoutCache` / `layout_cached`。**
   2026-10-25 已从代码、测试与基准删除。整章一次排完 + `BlockCache` 的现行路径，改一段实测 5.82 ms vs 整章 121 ms；两阶段整章累计约 204 ms，比现行 127 ms 更慢，而且会绕过 `BlockCache`。理由与数字在 `doc/阅读管线.md` 的 §十三“两阶段排版：量完之后不接”。

2. **不要引 FTS5。**
   中文两字查询 `MATCH` 会静默返回 0 行（`MATCH '一个'` → 0，`LIKE '%一个%'` → 1210 行）；索引体积是正文的 3.2–4.4 倍，建索引 1.5–2.5 s；现读现扫最坏 274 ms、典型 < 10 ms。实测表在 `crates/folio-core/src/search.rs` 的模块头。

3. **不要引第三方 CSS 引擎。**
   Stylo 不含布局且要写大量 DOM 胶水；`css-inline` 会抹平层叠语义；`taffy` 只解 flex/grid，不解文档流；`lightningcss` 会带进第二套 selector 实现，且未实测。真要评估先 `cargo tree` 看依赖闭合，再谈。

### 1.2 真正的成本

不是“到处都要优化”。排版与滚动的稳态已经达标：

- 真机 release 稳态帧 p50 **0.28–0.48 ms**、p90 0.50–1.58 ms。
- 场景构建 28–43 µs/帧；暖 shaping 230 µs。
- 字形环 15–44 ms 只在冷屏/新字进屏时出现，已被判定可接受（“滚动够用”）。

真正贵的是三件事：

1. **规模**：5k 本书架、10k 条批注、300 页 CBZ、整库搜索；这些路径现在有 N+1、整库扫描、无上限缓存。
2. **主线程 IO**：配置落盘、每本阅读设置写库、书架封面、笔记加载、开书、PDF 取字、OPDS 缩略图。
3. **数据安全**：迁移不是原子事务、删除与墓碑不在一个事务、zip 炸弹面、更新包完整性、传书 PIN。

以下三条已经按代码核实，旧文档作废：

1. **`justify` 已接线，不是“未接线”。** `crates/folio-core/src/layout/collect.rs:1637` 的 `justify_plan` 已在跑，`layout/tests.rs:2281` 有“除末行外每行摊满”的门。`doc/基础设施.md` §7.3 第 1 条写它“落进 `_ => 0.0`”，已过期。

## 3. 逐模块计划

### 3.1 `folio-core/content`

**规模与职责**：51,314 行 / 68 个文件（含测试）。21 个格式 provider、容器层、DOM、CSS 子集、锚点、命中测试、扫描。

**现状**

- 共享层是好的：ZIP 系共用一份中央目录索引（`content/format/zip.rs:34`）；EPUB 的图/章走会话级 `Container`（`content/document/book.rs:210`）；EPUB 读图片尺寸只读 32 KiB 头（`content/format/epub.rs:1376`）；搜索按章流式扫。
- 非测试代码里的 panic/unwrap/expect 只有 10 处，且都在有守卫的位置；坏容器普遍返回 `Err`/`None`。
- 问题集中在“定版式/单文件格式的资源访问”和“CSS 匹配每次重跑”。

**P0/P1**

#### CT-1（P1）CBZ 整本解压进内存

- **现状**：`content/format/cbz.rs:62` 在 index 时把每一页字节全部塞进 `Vec<(String, Vec<u8>)>`；`content/format/cbz.rs:83` 每取一页又重开一次 ZIP。300 页漫画 = 整本未压缩书常驻内存，翻页还反复打开容器。
- **动作**：页表只存条目名 + 尺寸（读图片头）；页字节走共享 `Container` 按需取；页字节缓存设上限（例如 16–32 MiB），按当前页 ± 2 预热。
- **收益**：打开时间与峰值内存都与页数解耦；翻页不再重开 ZIP。
- **风险**：图片头解析要覆盖 JPEG/PNG/WebP/GIF；读不出尺寸时退回“取整页再量”，但要计入上限。
- **验收**：300 页合成 CBZ，打开后峰值 RSS 先量基线再定阈值；`ContainerOpens` 不随翻页增长；取一页的条目读取次数 = 1。

#### CT-2（P1）PDF 每页重开文档

- **现状**：`content/format/pdf.rs:141` 的 `render_page` 与 `content/format/pdf.rs:152` 的 `page_text` 每次调用都 `PdfDocument::open`。模块头自己记了：3.6 MB / 45 页重开一趟 374 ms；一次取字 0.3–10 ms。
- **动作**：会话级缓存已打开的 `PdfDocument`（单线程句柄或每线程句柄）；`page_texts` 已有“一次开、逐页抽”的路径，保持；取不到字也缓存“这一页无字”。
- **收益**：定版式翻页/取字不再为“开文档”付几百毫秒。
- **风险**：`pdf_oxide` 的文档句柄是否 `Send` 要实测；不 `Send` 就每线程一份或固定在排版/渲染线程。
- **验收**：69 页 PDF 连翻 10 页，`PdfDocument::open` 次数 = 1；取字仍与逐页结果逐字节相同（保留现有契约测试）。

#### CT-3（P0）ZIP 炸弹面没有封顶

- **现状**：`content/format/zip.rs:89` 的 `read_to_end` 无上限；sniff 读 `mimetype` 无上限；中央目录条目数无上限；章节正文/图片解压无上限。导入解包那 512 MiB 上限只覆盖 `comic_cache` 那一条。
- **动作**：统一三道上限——条目数、单条目解压后字节、总解压字节；sniff 只读有限头；超限返回 `Error::TooLarge`，不 panic。上限按格式分档（正文/图片/漫画），写进常量并在诊断 dump 里可见。
- **收益**：坏包/恶意包在内存暴涨前被拒绝；移动端不会因一本书被系统杀。
- **风险**：上限太紧会误伤超大但合法的画册；先按现有语料的最大值留 2–3 倍余量。
- **验收**：合成炸弹（10k 条目 / 单条 1 GiB / 总 10 GiB）在内存暴涨前拒绝；`cargo fuzz` 跑 `sniff`/`zip` 入口 1 小时无 crash；回归夹具入库。

#### CT-4（P1）CSS 匹配没有缓存，改字号全书重匹配

- **现状**：`content/format/css/computed.rs:1081` 的 `cascade` 每次 typeset 都整树重跑；`content/format/css/mod.rs:280` 的 `matched_in` 对每个元素扫全部规则、分配 `hits` + 4 个层级 `Vec` 并排序；`::first-letter` 每个元素再扫一遍。字号变化只该影响层叠，不该重匹配。
- **动作**：把“匹配”与“层叠”拆开，按 `(章内容哈希, RuleSet 哈希)` 缓存每个节点的命中规则；字号/行距变化只重层叠。`::first-letter` 只在该章存在相关规则时查询。
- **收益**：改字号从“整章重匹配 + 重层叠”降为“只重层叠 + 增量排版”。
- **风险**：缓存键漏掉某一层规则会导致样式静默错；键必须覆盖作者 CSS、章内 `<style>`、读者层规则三处。
- **验收**：计数门——改一次字号，`RuleSetParses`/匹配次数 = 0，cascade 次数 = 1；与 `DomParses` 同一口径。关掉缓存时该门必须红。

#### CT-5（P2）EPUB 的 container.xml + OPF 解析两遍

- **现状**：`content/format/epub.rs:173` 的 `font_bytes` 又走一遍 container/OPF；导入路径还会 shape → sniff → identify → parse 开 3 次 ZIP。
- **动作**：OPF 结果 memo 进 `BookDocument`/provider，字体与导入复用；导入把已开的容器传下去（与 IG-1 同一刀）。
- **验收**：一本 EPUB 导入 `ContainerOpens` 从 3 降到 1；取字体不再重解析 OPF。

#### CT-6（P2）单文件 provider 每张图重读整本

- **现状**：RTF/FB2/DOC/MHTML 的 `image_bytes` 会重新读文件、重新解析整本。
- **动作**：按书缓存一次解析后的资源表（与 `section_texts` 同口径，关书即走），资源表设上限。
- **验收**：取 20 张内嵌图，整本重读次数 = 1。

#### CT-7（P2）DOCX/ODT/DOC 每章扫两遍

- **现状**：`visible_chars` 走完整 DOM 解析，`chapter_images` 又走 tokenizer 扫描。
- **动作**：一次扫描同时产出正文与图片引用；用计数门钉住“每章一次”。
- **验收**：每章 `DomParses` = 1，图片引用与正文来自同一次扫描。

#### CT-8（P2）RAR/7z 解压两份实现、逐条目重开

- **现状**：`content/format/archive.rs` 与 `content/format/comic_cache.rs` 各一套 RAR/7z/tar 提取；压缩包含多条目时逐条重开是 O(n²)。
- **动作**：抽共享 `extract_all`，一次遍历；漫画缓存复用。
- **验收**：一个 100 条目的 RAR，容器重开次数 = 1。

#### CT-9（P2）锚点/命中/几何的线性扫

- **现状**：`content/anchor.rs:599` 的 `line_at_offset` 全章线性扫；`CharLines::build` 按 `own[..start].chars()` 重复数；`content/hit.rs:243` 的 `rects_for_range` 永远扫全行；`layout/geometry.rs:494` 的二分只在 `stacked` 时生效，有高行内图时退回线性。
- **动作**：为“非叠放”建最大底边前缀索引；`line_at_offset` 走 `CharLines`；`rects_for_range` 强制/推荐窄区间；缓存 `TextMap::chars`。
- **验收**：恢复落点/划词路径的扫描行数上限；`RectLines` 计数不随章长线性增长。

#### CT-10（P3）层叠分配与 `letter-spacing`

- **现状**：`cascade` 每元素克隆父样式、每个文本节点再克隆；`letter-spacing` 解析、继承、进哈希，但无人读（inert）。
- **动作**：只在该章存在 `::first-letter` 规则时查询；`letter-spacing` 要么四处一起接（宽度表、`RunStyle`、绘制、`char_edges`），要么把字段摘掉，不要半接。
- **验收**：若接，四处的测试同时绿；若不接，`css-gap` 不再把它算成已支持。

#### CT-11（P1）词缝那条判据要按「这一行的 em」估，不是按当前字的墨高

- 状态：待做（2026-10-29 量完，写在这里的就是量出来的数）。
- **现状**：`content/format/pdf.rs` 的 `text_layer` 用「缝 > **当前这个字**的墨盒高 × 0.25」
  判词缝。墨盒高不是字号：大写 `T` 是 7.94 pt、小写 `u` 只有 5.42 pt（`x` 高），同一行
  里阈值差 1.5 倍，而 poppler 用的是这一族的空格宽。
- **实测**（`tests/fixtures/oss/pdf/wps-paper.pdf` 前两页，裁判 `pdftotext -raw`，
  比的是词序列）：

  | 阈值 | 我们交出的词数 | 与 poppler 931 词比：多切 | 少切（粘住） |
  |---|---|---|---|
  | 0.25（现在） | 1529 | **1319** | 721 |
  | 0.45 | 913 | 558 | 576 |
  | 0.70 | 469 | 229 | 691 |

  两头都错，而且**同一行里分不开**：`TITLE OF THE PAPER` 那一行，词内 `I`→`T` 的缝是

### 3.3 `folio-core/store`

**规模与职责**：8,392 行 / 12 个文件（含测试）。SQLite、27 个迁移、书架/进度/批注/书签/集合/翻译、同步落库。

**P0**

#### ST-1（P0）迁移不是原子事务，v8 的 `user_version` 先写

状态：已完成（2026-10-29，未提交）。一条迁移 = 一笔 `unchecked_transaction`，`user_version` 与 v8 的 Rust 回填都在同一笔里。
门：`a_migration_that_fails_halfway_leaves_the_library_at_the_previous_version`（给 `chapters` 装 `RAISE(ABORT)` 触发器把回填打断，验版本仍停在 7、`chapter_text` 没被删、撤掉注入后能完整升上去；把事务拿掉这条当场红：`left: 8 right: 7`）。

- **现状**：`store/mod.rs:125` 逐条 `execute_batch` 后单独 `pragma user_version`；中间崩溃会留下“表已建、版本没升”或“版本升了、`finish_v8` 没跑”的库，下次打开重跑 `CREATE TABLE` 直接失败。`store/mod.rs:138` 在 `finish_v8` 之前就写了 8。
- **动作**：每条迁移 `BEGIN IMMEDIATE … COMMIT`，`user_version` 与 DDL/回填同一事务；v8 的 Rust 回填要么在事务内完成，要么做成完全可重入后再升版本。`VACUUM` 不能进事务，保持在迁移循环之后。
- **收益**：断电/杀进程不会留下半套 schema；损坏库不会从“可修”变成“打不开”。
- **风险**：长迁移持写锁更久；v8 回填可能慢，需要先量最大旧库的回填时间。
- **验收**：注入“DDL 后 / 版本前”崩溃，重开必须成功且旧数据可读；v5/v8/v12/v19/v20/v21 各加一条真实旧库→新库夹具；损坏库“只报错不覆盖”的测试继续绿。

#### ST-2（P0）删批注/书签与写墓碑不在一个事务

状态：已完成（2026-10-29，未提交）。删除与恢复四条路都各包一笔事务，墓碑写入并成一处 `sync::record_tombstone`。
门：`a_failed_tombstone_write_rolls_back_the_delete`（批注与书签各半；注入让墓碑那一写失败 ⇒ 那一行必须原地还在；撤掉注入要删得动且留下 1 条墓碑）。拿掉事务即红：`left: 0 right: 1`。

- **现状**：`store/annotations.rs:201` 先 `DELETE` 再 `INSERT sync_tombstones`，中间崩溃会导致下次同步“复活”这条删除；书签同构。
- **动作**：`unchecked_transaction()` 包住两写；恢复路径同样。`write_tombstone` 与删除放同一事务。
- **收益**：删除不会跨设备复活。
- **风险**：低；只改事务边界。
- **验收**：注入删除后/墓碑前的失败，重开 + 跨设备合并后不复活；书签同一条。

#### ST-3（P1）墓碑时间戳可倒退

状态：已完成（2026-10-29，未提交）。`ON CONFLICT … DO UPDATE … WHERE excluded.deleted_at > sync_tombstones.deleted_at`。
门：`a_late_tombstone_never_moves_the_deletion_back`（本地 t 已知 → 合并 t−50 不许动；合并 t+50 要推进）。去掉那句 WHERE 即红。

#### ST-4（P1）`book_cover` 在库锁内读文件

- **现状**：`store/books.rs:405` 持 `conn` 锁做 `cover::resolve` + `fs::read`，所有 DB 读者排在一张图上。
- **动作**：锁内只取 `path/cover_hash/cover_mime`，释放锁后再读文件；与 SH-1 一起把“先缩略图后原图”放到调用方。
- **验收**：并发 100 次书架查询 + 一次封面读，查询不被文件 IO 阻塞（用线程计时或锁等待计数）。

#### ST-5（P0/待拍板）`prune_missing` 会连数据一起删

- **风险**：书架会出现“文件不在了”的条目，需要 UI 表达；这是可接受的成本。

**P1**

- **现状**：`net/transfer/mod.rs:76` 绑 `0.0.0.0`，`:105` 把 PIN 写日志，配对码只有 10k 组合且无失败计数。

## 7. 不做什么（已否决/已量过）

1. **不重做两阶段排版 / 不恢复 `LayoutCache` / `layout_cached`**：2026-10-25 已从代码、测试、bench 删除；两阶段整章累计约 204 ms，比现行 127 ms 更慢，且绕过 `BlockCache`。
2. **不引 FTS5**：中文两字查询 `MATCH` 静默 0 行；索引体积是正文 3.2–4.4×，建索引 1.5–2.5 s；现扫最坏 274 ms、典型 <10 ms。
3. **不引第三方 CSS 引擎**：Stylo 不含布局、`css-inline` 抹平层叠、`taffy` 只解 flex/grid；`lightningcss` 未实测，先 `cargo tree` 再谈。
4. **不做 UMD**：本机零样本，规格只有互相矛盾的逆向笔记。
5. **不嵌 WebView、不把页面渲成整张图**：文本选择、锚点、批注都建立在文本/字形上。
6. **不重接 `justify`**：已接线并有测试；旧文档那条作废。
7. **不重接 `SceneRuns` 行单元表**：2026-10-15 已接线，门已摘 `#[ignore]` 且绿。
8. **不为稳态帧/glyph ring 做 micro-opt**：真机 p50 0.28–0.48 ms、场景 28–43 µs、暖 shaping 230 µs；字形环 15–44 ms 已被判定可接受。除非真机量到 >16 ms/帧，否则不动。
9. **不为了“Address 直读”去拆 `Container` 锁**：当前是一次开、查表、锁共享；文档承认锁还在，但滚动取图/取章已经走容器，收益要先量。
10. **不做全仓 `cargo fmt` drive-by**：只格式化本次改到的文件；本仓库有历史 reflow 漂移的教训。
11. **不为了让旧库兼容而拒绝迁移**：库可以重建，但迁移本身必须原子、可恢复；这两件事不是一回事。
12. **不把“缓存命中率”当装饰**：没有 bytes/hits/misses 的缓存不算缓存，先接诊断再谈优化。
