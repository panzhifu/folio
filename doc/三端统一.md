# 三端统一：Linux / macOS / Windows

这份文档定的是一批要做的活与**「做完」的定义**，不是现状介绍。现状每一条都带 `文件:行号`，
是 2026-11-04 在**现钉的那个 fork 版本**上量出来的，不是照旧文档抄的 —— 量完的结果有三条与
旧说法相反，写在下面各自那一节里。

读者只有一个：这台仓库的开发者。他是 solo 开发兼设计，**手上没有 macOS 也没有 Windows 的
真机或虚拟机**（2026-11-04 亲口确认）。这一条决定了整份文档的验收口径：

> **凡是要「看一眼才算完」的改动，在这两份平台上都不算做完。** 能自动跑的闸只有 CI，
> 所以这一批第一件事是把 CI 抬到三端，后面每一条的验收都写成「CI 绿 + 明确标注未验」。
> 谁把「编过」写成「做好了」，就是在给下一个读者（包括未来的自己）造一个假账。

## 做完 / 没做完，这四档说得清

| 档 | 含义 | 例 |
|---|---|---|
| **三端验过** | 三台设备上都看过画面或听过声音 | 翻页动画的一致性目前不属于这一档 |
| **CI 验过** | 三端各自编译 + 跑单测绿，画面未看 | 本批的多数交付落在这一档 |
| **只 Linux 验过** | 只有开发机这一台真看过 | 卷页、听书、毛玻璃在 mac/win 的实际表现 |
| **未验** | 写完了但没有任何环境跑过 | 不做的事也在这一档里明写 |

## 事实基线（2026-11-04 量的）

- 桌面平台分叉在 folio 侧一共五处，全部列得出：
  [`turn_animation/mod.rs#L124-L137`](#一翻页仿真卷页)（卷页那道 cfg）、
  `ui/platform/desktop.rs:7`（Windows release 用 `windows_subsystem` 藏控制台，对的）、
  `ui/platform/mod.rs:143,175,346`（自装 / 系统分享面板 / 背光压暗，三格都是 Android 独有，
  三端一致地没有）、`ui/platform/mod.rs:216-222,261-272`（打开目录与链接的三家 opener，对的）、
  `ui/features/reader/components/selection.rs:1213` 的 `RENDERS_SHARE_CARDS`（分享卡片只有移动端，
  因为离屏出图那套只在 gpui-mobile 里 —— 这是**三端一致**的缺，不是某一端缺）。
- CI：`.github/workflows/ci.yml` 只有 `check`（ubuntu-24.04）与 `android`（ubuntu-24.04）
  两个 job。macOS 与 Windows 只在 `release.yml` 里「能编能出包」，**从没跑过一次测试**。
- 签名：macOS 出 `.app` 的 zip，无 codesign、无公证；Windows 出 NSIS + zip，无代码签名。
  两端用户第一次打开都会撞上 Gatekeeper / SmartScreen 的警告。
- 路径与权限：`infra/paths.rs` 已经用 `dirs`（`crates/folio-core/Cargo.toml:14`，
  工作区 `dirs = "6"`）走 XDG / `dirs::config_dir` / `dirs::data_dir`，只在读不到时退回
  `$HOME` 点目录。但有**两处绕过了它直接读 `HOME`**：`ui/host/desktop.rs:77`（分享与下载的
  落点 = `$HOME/Downloads`）与 `ui/services/library.rs:68-71`（整机扫描根）。Windows 一般
  只有 `USERPROFILE`，于是这两处双双落空：前者退到临时目录，后者退到数据根。
  另外 `infra/config.rs:1566` 那句 `chmod 0600` 在 `#[cfg(unix)]` 分支里，Windows 上
  `config.json` 里那把翻译密钥没有等价的权限收紧。

## 一、翻页仿真卷页：那道 cfg 是过期的，删

**旧说法**：`turn_animation/mod.rs:130` 写着「Metal 与 DirectX 两条渲染路径还没实现
page_curl 的绘制（渲染器收到该批次只会跳过）」，`CHANGELOG.md` 顺着它写着两端不支持卷页。

**量到的**：现钉的 fork（`Cargo.toml` 里 `gpui-folio` 的 `9df6f75`）里

- `gpui-pre-apple/src/page_curl.rs` 存在，`metal_renderer.rs:147` 挂着
  `page_curl: page_curl::PageCurlResources`，`:399` 构造、`:526` 随尺寸失效、
  `:872` 绘制，并消费 `PrimitiveBatch::PageCurlMeshes`；
- `gpui-pre-windows/src/directx_renderer.rs:48` 有 `page_curl: Option<(ID3D11Device,
  PageCurlResources)>`，`:392`、`:472` 两处接 `PrimitiveBatch::PageCurlMeshes`。

也就是说：**这条 cfg 挡的不是一个不存在的能力，而是我们自己锁上的门。**

**要做的**：删 `mod.rs:124,134-136` 那三道 `cfg`（`Curl` 三端都指向 `&CURL`），
把这段注释改成「上游两条路径都已实现，folio 侧不再降级」，并改 `CHANGELOG.md` 那句过期话。
folio 侧代码净减 3 行 + 两处注释。

**验收**：CI 三端绿之后，这一条仍停在「只 Linux 验过」—— 卷页的折痕、接触影、背面是不是
下一页的真字，只有眼睛能判。**下一步该由谁做**：找一台 mac 与一台 Windows 各跑一次
（读者群或云主机都行），看一帧。在那之前 `PageTurn::Curl` 在这两端算「可用但未验」。

**风险**：Metal / DirectX 那两条实现从没被 folio 的批次喂过（我们只在 wgpu 上跑过），
第一次可能 panic 或画歪。这一条真要在 CI 里加一道的话，只能钉到「构造得出这个 primitive」，
钉不到画面。

## 二、点文件就开书：三端都不通，补口都在

**现状**：全仓 `crates/*/src` 里没有任何地方读 `std::env::args`（只有 `examples/` 读），
也不调 `on_open_urls`。而上游有：`gpui-pre/src/app.rs:359` 暴露
`App::on_open_urls(callback)`，Apple 平台（`gpui-pre-apple/vendor/gpui/src/platform.rs`）
与 Windows（`gpui-pre-windows/src/platform.rs`）都实现了它；Linux 的平台实现里搜不到
`on_open_urls` —— 那一端只能自己读 argv。

打包面各缺一格：`packaging/linux/folio.desktop` 写了 `%u`（桌面环境会传路径过来，
但程序不读）；macOS 的 `Info.plist` 已声明 epub/pdf（`release.yml:344-350`，`CFBundleDocumentTypes`）；
`packaging/windows/folio.nsi:63-85` 装的那一段只写卸载表，**全文件搜不到 `HKCR` 或任何文件关联**，所以 Windows 上双击
`.epub` 根本不会想到 folio。

**要做的**（一处入口，三端各一小段）：

1. `ui/platform` 加一个「待开的文件」槽：mac/win 在 `run_desktop` 里挂
   `application().on_open_urls(...)`，Linux 在读配置那一步之前收集 `std::env::args()`
   里存在的 `.epub/.pdf/.txt/…` 路径。**已开窗**与**尚未开窗**两条都要走同一个入口
   （macOS 的二次打开事件在窗已开之后才来）。
2. 外壳收到路径 → 交给 `Library` 那条导入/开书链（复用书架的 `Open`，别新开一条），
   路径不存在或格式不认时**当场说一句**，不要静默。
3. NSIS 补 `HKCR\.epub`（以及 pdf/txt/mobi/epub 那一族）的 ProgID 与 `shell\open\command`，
   卸载时清掉；`.desktop` 不需要动（已经写了 `%u`）。

**代价**：folio 侧约 +120～180 行（含 NSIS），净增都在入口那一层；不改任何渲染路径。
**验收**：CI 三端绿 + Linux 这台真点一次（这一条在 Linux 上可以算「验过」）；
mac / Windows 双击只能算「CI 验过」，关联写没写对要看注册表 —— 我这边没法看。

## 三、macOS 与 Windows 听书：不是上游没做，是我们把依赖门关着

**现状**：`crates/folio-core/Cargo.toml:125` 把 `tts` 的依赖门写成
`cfg(any(all(target_os = "linux", not(target_env = "ohos")), target_os = "android"))`，
`speech.rs:356` 那侧给其余平台一份 `engine()` 恒回 `None` 的 stub，界面按「这台设备没有
这一格」降级（`model/speech.rs` 的 `speech_entry_visible`）。

**量到的**：`tts` 0.26.3 自带这些后端 —— `src/backends/` 里有 `appkit.rs`、
`av_foundation.rs`（macOS / iOS）、`tolk.rs` + `winrt.rs`（Windows），依赖分别挂在
`cfg(any(target_os="macos", target_os="ios"))`（cocoa-foundation / core-foundation / objc）
与 `cfg(windows)`（`tolk`、`windows`）上。所以打开是「改依赖门 + 拆 stub 的对应臂」，
不是从零写后端。

**要做的**：

1. `Cargo.toml:125` 的门加上 mac 与 Windows（鸿蒙那一格**必须继续排除** —— 它的三元组报
   `target_os = "linux"` 而 sysroot 里没有 `-lspeechd`，这条已经踩过一次，理由就写在门旁边）。
2. `speech.rs` 的 stub 改成只兜「真的没有后端」的那几端，mac/win 走真 `imp`。
   专职线程那一层不用改（`Tts` 句柄不能跨线程这条约束在所有平台同样成立）。
3. Windows 的 `tolk` 要装 SAPI5 之外的东西吗？不 —— Tolk 是找现有语音引擎，
   系统没装任何引擎时它拿不到声音，这与 Linux 上没装 speechd 是同一类「这台机器没这格」。
   **界面那条降级路径不变**，所以探测失败不会弹错误，只是入口不出现。
4. CI 加的两端 job 会是我们唯一能跑的检：编译过 + 现有单测过。

**代价**：依赖门与 stub 各一臂，folio 侧 ±40 行；`Cargo.lock` 会多进 mac/win 的 objc /
windows 那一族（只在各自平台的 target 下）。
**风险与「算不算做完」**：音质、中文能不能念、后台切换时的行为，**全部未验**。
这一条交付后的诚实说法是「mac 与 Windows 有听书入口了，好不好听没人听过」。
音色质量与「中文要念得对」这两件事**不进这一批**。

## 四、Windows 的路径与密钥：先复用已有的那一份

1. `ui/host/desktop.rs:77` 与 `ui/services/library.rs:68-71` 那两处直读 `HOME` 的，
   改成走 `infra/paths`（那里已经在用 `dirs`）。下载/分享落点要的是「用户找得到的目录」，
   `dirs` 没有 Downloads 这一格 —— 在 `paths` 里加一个 `downloads_dir()`：
   Windows 读 `FOLDERID_Downloads`（`dirs` 拿不到，走 `SHGetKnownFolderPath` 或直接
   `USERPROFILE/Downloads` 并校 `is_dir()`），mac/linux 保 `$HOME/Downloads`，
   都拿不到才退临时目录，**并且退了就打印出来**（现在这条已经在退的时候不吭声）。
   两处调用点一处判据，别长出第二份。
2. `config.json` 里那把翻译密钥：Windows 上 `chmod` 不存在。三条路选一条 ——
   （a）只写文档说明「这台机器的文件权限由 ACL 管，folio 没动它」；
   （b）Windows 上用 DPAPI/凭据管理器存那一格；（c）密钥不入配置文件，单独一个文件并
   显式设 ACL。这一条**先不动代码**，等确认：它要新依赖或新平台代码，而收益是肩窥级别的
   安全，不值得夹在统一这一批里顺手做。写在这里是为了别让它消失在聊天里。

**代价**：`paths` +约 40 行、两处调用点各改一行、一条门（`downloads_dir` 三端都回真路径）。
**验收**：Linux 绿即算验过；Windows 那一支只能算 CI 验过。

## 这一批不做的，各有一条理由

- **底栏毛玻璃**。`backdrop` 这个词在 `gpui-pre-apple` 与 `gpui-pre-windows` 的渲染器里
  **零命中** —— 不是跳过，是没写。要统一就得在 fork 里给 Metal 与 DirectX 各写一趟
  「从屏上拷底下那块 → 降采样 → 两趟可分离高斯」，是这份清单里唯一一条**上游活**，
  量级和上面四条不是一个数量级。现在的样子（mac/win 只有半透明 tint）留着，
  但要在 `ui/shell/navigation/surface.rs` 那段注释上写清「只有 wgpu 实现糊，另两端是 tint」，
  别再让人以为是 folio 的 bug。
- **代码签名与公证**。要 Apple Developer ID（年费）与 Windows 签名证书（或 Azure
  Trusted Signing），是**账号与钱**的决定，不是代码的决定。现状不写进这一批，
  但它在 `doc/development.md` 的发版一节里该有一句「两端都不签名」。
- **CI 加 macOS / Windows 的测试门** —— 这一条不在上面四条里，但它是**前提**：
  没有真机时它是唯一自动闸。做法：`check` 拆成矩阵（`ubuntu-24.04` / `macos-14` /
  `windows-2022`）跑 `cargo test -p folio-core --lib` 与 `-p folio-app --lib`。
  已知会咬人的地方：依赖真实系统字体与 fontconfig 的门（本仓库有一批 `#[ignore]`
  的真样本门，它们在各端本来就该跳过）、`/tmp` 语义差异、行分隔符断言。
  第一次跑一定会红在几个「只在这台设备上成立」的断言上，那是要改测试的口径，
  不是要关掉 job —— 这句话写在这里，是给下次想撤掉那两个 job 的人看的。
- **全局快捷键 / 托盘 / 单实例 / 保持唤醒**：三端一致地没做（全仓零命中），
  这不是「哪一端不足」，别混进这一批。
- **分享卡片（划词出图）只有移动端**：离屏出图那套住在 gpui-mobile，桌面三端同缺，
  同一类「三端一致的缺」，不在这批。

## 顺序

1. **CI 抬到三端**（前提；先红的那几条测试口径先修，后面的活才有检）。
2. **卷页那道 cfg**（一行删 + 两处改口，最能立刻看出 CI 有没有真在跑）。
3. **点文件就开书**（三端各一小段 + NSIS，Linux 这一端当场能验）。
4. **Windows 路径**（复用 `paths`，小）。
5. **mac / Windows 听书**（依赖门与 stub，放最后：它的交付名「未验」最长，
   而且 `Cargo.lock` 会多进一族平台依赖，最好让前四条先把 CI 站稳）。
