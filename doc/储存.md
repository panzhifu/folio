# 储存 API 设计（SQLite 书库）

`Store` 是一个类型、一把锁；前端读书架 / 进度 / 批注 / 统计，导入写它。
实现按主题拆文件，API 按主题列。**机制住 folio-store crate**（2026-11-12 阶段四拆分，
原 folio-core::store 与书库资产的落盘约定原样搬去；`folio_core::store::*` 旧路径经
模块别名沿用，rusqlite 随行）。错误自持（`folio_store::Error`：SQL、载荷 JSON、
带标签的本地 I/O、集合名校验——原 core 伞枚举的 `Sql` / `EmptyCollectionName` 两格
删除，伞枚举经 `From` 收编整条链）。卡点「book_settings → config」由阶段二先解掉：
store 只碰 `BookSettings` 的数据与列编解码（都在 folio-model），咬配置的 effective/record
行为经 `BookSettingsExt` 留在 core，store 的生产代码一行不沾。

## 使用顺序（一屏看完）

```rust
let store = Store::open_default()?;            // 或 open_at(path) / in_memory()（测试）
let items = store.shelf("")?;                  // 书架清单
store.set_position(book_id, mode, &locator)?;  // 离开书时存位置
let pos = store.position(book_id)?;            // 回来时取
```

## API 一览

### 书目、来源与阅读版本

`book_id` 沿用本地关联，新增 `book_uuid` 作为稳定书目身份；完整 SHA-256 只描述版本字节。
书目 ID 由持久高水位在单条 INSERT 中分配，移除最高 ID 或重开数据库都不复用；
来源、批注和书签 ID 同样不复用（包括本地新增与同步写入），旧会话和迟到回调不能命中新对象。
撤销删除还核对原 UID 与所属书目，身份冲突时拒绝恢复，不覆盖另一条记录。
v32 迁移只复制旧登记哈希与本机记录归属到 `(rev_no=0,index_generation=0)`，不打开书文件。
这份 Legacy 标为 `legacy-unverified`，生产阅读须先由导入层捕获并验证固定副本。

```rust
store.register_import(ImportRegistration { .. }) // 书目、首版索引、来源一次事务登记
store.bind_source(book_id, locator, kind, primary)
store.mark_source_dirty(source_id)              // 观察代递增，事件不直接改内容
store.observe_source_at(source_id, generation, fingerprint)
store.reserve_revision(book_id)                // 预留本书内新 rev_no
store.ready_revision(RevisionReady { .. })       // 独立存候选索引，不动当前章节
store.adopt_revision(book_id, target, expected, allow_leased)
store.acquire_revision(book_id)                 // 同锁读取快照并取得 RAII 阅读租约
store.revision_snapshot(book_id, fence)         // 读取指定版本的独立索引
store.reserve_reindex(book_id)                  // 同字节换 index_generation
```

`RevisionFence` 同时包含内容版本与坐标代。自动采用与阅读租约在同一连接锁下协调；
本书有任意阅读租约时后台返回 `ReadersActive`，显式切换才可采用。旧会话写入须在同次
数据库临界区检查 fence。`Ready` 只接受幂等重复，不允许把同一版本的索引改成另一份。
新内容采用时保留用户书名/作者和书内偏好，兼容读字段与当前章表一次事务切换。

Source 的 locator、权限状态与指纹仅为本机事实，主源自动核对，备用源不抢主源。
旧代捕获不能用 `observe_source_at` 覆盖新观察；移除书目留下来源抑制记录。
恢复后的 `relink-required` 来源不参与自动读取。每版记录显式 `library_root`，当前
`books.managed_root` 仅为兼容投影，资产定位不再对新版本从父目录猜根。

当前版、上一份保留版和所有租约占用版不能回收。`prunable_revisions` 与
`detach_revision_file` 只管理登记引用，实际删除由 core 核对应用所有权后执行；
旧版本字节回收后仍保留身份、索引、笔记建锚版本与墓碑元数据。

### 开库

```rust
Store::open_default() -> Result<Store>   // 默认路径
Store::open_at(path: &Path)              // 指定路径
Store::in_memory()                       // 测试用
store.backup_to(path)                    // 整库备份
store.vacuum() -> Result<u64>            // 回收空间，回可回收字节数
Store::inspect_backup(path)             // 只读检查 schema、quick_check 和外键
store.relocate_backup_library(old, new)  // 仅在隔离恢复副本中重定位，保留 book_id
store.checkpoint_restored()             // 恢复副本 checkpoint 后关闭再激活
```

### 书目与书架（books）

```rust
store.add_book(path, &meta) -> Result<i64>          // 入库，回 id
store.shelf(query) -> Vec<ShelfItem>                // 书架（可搜索）
store.shelf_grouped(query, by) -> Vec<ShelfGroup>   // 按作者 / 分组聚合
store.book(id) / book_meta(id) / book_cover(id)     // 单本、书目、封面字节
store.book_by_hash(hex) -> Option<BookRow>          // 按内容身份找（导入去重用）
store.set_book_meta(id, title, authors)             // 改书名 / 作者
store.remove_book(id)                               // 删书（连副本与缓存）
store.unavailable_sources()                        // 只报告源文件不可用，不删除记录
store.touch_opened(id)                              // 记「打开过」
```

### 进度与已读

```rust
store.set_position(book_id, mode, &locator)          // 存阅读位置
store.position(book_id) -> Option<(mode, Locator)>   // 取
store.mark_chapter_read(book_id, idx) / read_chapters(book_id)
```

### 批注 / 书签 / 集合

```rust
store.add_annotation(...) / annotations(book_id) / update_annotation / delete_annotation
store.add_bookmark(book_id, &anchor) / bookmarks(book_id) / delete_bookmark
store.create_collection(name) / add_to_collection(coll, book) / books_in_collection(coll)
```

- 批注与书签挂在 `TextAnchor`（文本指纹）上，文档变了能找回位置。
- 删除都配一条 restore（撤销用）。

### 阅读统计

```rust
Snapshot::load(&store, range, anchor, tz_offset_secs)   // 统计屏一份全拿
```

分桶、补零、连签都在这层算好，界面只摆；**时区是参数**。

### 笔记聚合（notes）

跨书把批注 + 书签折成 `BookGroup` 清单（分组、排序、封面字节齐），笔记屏直接摆。

## 优化（现有实现里已经做了的）

- **一次调用只上锁一次**——公开方法拿守卫调 `*_in(&conn)` 助手，助手不再碰锁，
  `Mutex` 不可重入，方法套方法就是自锁。
- **拆文件不拆实体**——主题各一份文件，`Store` 仍是一个类型一把锁。
- **迁移只增不改**——schema 是日志式清单，老库一路升上来不重写。
- **封面字节去重**——同 hash 的封面盘上只留一份。
- **口令不同步**——读者口令按本机存，刻意不进同步。
- **缺书保留记录**——启动只报告 Missing / NotFile / Unreadable；批注、书签和进度保留，文件回来后仍可读取，明确删除另走用户操作。

备份恢复只在新目录操作，保留书目身份、阅读位置、书内设置、批注和书签。完整备份要求书文件可读，只有数据的备份保留缺书记录。配置和主题放恢复副本的 `preferences/`，数据库与资产留在副本根；准备失败不修改原库，完成后重试不覆盖新编辑。下一进程打开 Store 前才按稳定根的启动指针激活，已选副本损坏时停止启动，不自动回退。凭据选择与失败语义见 [备份恢复 ADR](adr/2026-11-18-备份恢复激活与凭据.md)。
