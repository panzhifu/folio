# 地基 API 设计（folio-base）

不解决业务问题，但每条业务线都要用。不认识书本、格式、SQLite、网络、界面。
顺序即启动顺序：先定目录 → 再加载配置 → 再初始化日志 → 然后各业务线各取所需。

## API 一览

### 1. app_dirs — 获取软件目录

```rust
pub struct AppDirs {
    pub books: PathBuf,    // 书库位置
    pub config: PathBuf,   // 配置位置
    pub logs: PathBuf,     // 日志位置
    pub cache: PathBuf,    // 缓存位置
}
pub fn app_dirs() -> AppDirs
pub fn set_app_dirs(config_root: PathBuf, data_root: PathBuf)   // 平台入口先定根
pub fn prepare_dir(path: &Path) -> Result<()>                   // 用前建目录
```

- **第一个 API**：软件的四个落点都在这一格，全仓库要路径只能问它，不自己拼。
- **已实现**：`AppDirs` / `app_dirs()` 落在 folio-base::paths；缓存收敛为
  `<数据根>/cache`（`cache_dir()`），漫画解压缓存改挂它底下（`<缓存区>/comics`），
  磁盘路径一个字节没变，老库的解压产物不用搬。

### 2. config — 配置：加载 / 编辑 / 更新

```rust
Config::load() -> Config              // 加载；缺文件给默认，环境变量可整体忽略
Config::load_resolved() -> Resolved   // 合并默认后生效的那份
config.save() -> Result<()>           // 编辑后落盘（save_to(path) 可指定路径）
pub const CONFIG_VERSION: u32         // 版本迁移：老配置一路升上来
```

- **加载**——文件缺格按 serde 默认补，格式版本记在文件里。
- **编辑**——改字段 + `save()`，落盘走临时文件替换，不写坏原文件。
- **更新**——`CONFIG_VERSION` 认版本，老文件升上来不重写不丢格。
- **现状说明**——配置住在 `folio-core::infra::config`：schema 引着 folio-model
  的公共类型（`reading::ImageScale`、`novel::{Edits, Marker}`，出厂表与合成引擎仍住
  folio-format）与 core 的 `account::AccountKey`，整搬进 folio-base 会打破它零业务
  依赖的铁律；`infra/mod.rs` 已把它规划为「第二步 settings 层」。地基只保证
  目录（§1）与日志初始化（§3）这两格。

#### 配置还能怎么优化（供讨论）

- **拆文件**——config.rs 3430 行、17 节、约 40 个类型挤一个文件；照 store 的拆法
  「拆文件不拆实体」，按主题分（阅读 / 外观 / 书库 / 云盘 / AI 与翻译…），
  `Config` 仍是同一个类型。
- **变更通知**——`Resolved` 是一次读出的快照，改了配置别人不知道；改成共享句柄 +
  变更事件（带版本号），改一格全仓库能响应。第一个落点是日志等级热重载
  （tracing filter 重挂），不用重启就生效。
- **save 节流**——save 是显式调用，没有脏标记与节流的机制；设置屏高频控件
  （拖字号这类）若逐次落盘，加脏标记 + debounce 合并成一次写。移动端闪存
  在意的就是这个写入频率。
- **未知键报告**——`flatten_keys` 已经把文件摊成点分键（provenance 在用），
  顺手 warn 一次「文件里有、代码里没有」的键：那是改名 / 删键后的残留，
  现在静默忽略。
- **provenance 上屏**——`Layer`（default / file / env / book）已经在记每一格
  是哪层定的；设置屏可以显示「这格来自书内差量」，并给「重置此格」按钮。
- **节级迁移（远期）**——拆节之后每节可自带版本号，迁移粒度从整份缩到节；
  现在还是 v1，先记着不动。

### 3. logging — 用配置初始化

```rust
pub fn init(logging: &Logging, extra: Option<BoxedLayer>) -> Result<()>
```

- **吃配置那一节**（等级、分层 `Layer`），日志文件落在 `app_dirs().logs`，
  轮转与旧文件清理归它（`log_file` / `purge_rotated`）。
- 顺序依赖：`app_dirs` 定根之后才能初始化。

### 4. task — 后台作业池

```rust
TaskManager::new(workers)
manager.submit(job) -> TaskHandle<R>          // 默认优先级
manager.submit_with(priority, job)            // 四档优先级
handle.cancel_and_wait() -> bool              // 取消并等收尾
manager.shutdown()                            // 跑完已排的再收线程，幂等
```

作业里拿 `StageCtx` 报进度：`cancel()` 标志、`item(done, total)`、
`bytes(done, total, name)`、`message(...)`。

### 5. cancel — 协作式取消

```rust
Cancel::new() / trigger() / triggered() -> bool
```

作业与网络共用一个标志位，分段检查，不硬杀线程。

### 6. identity — 内容寻址

```rust
sha256_of_bytes(&bytes) -> String
```

字节 → 身份 → 书库副本文件名；去重与找书都靠它。

### 7. budget — 内存预算

```rust
MemoryBudget / Pressure / EvictStep
```

全局预算 + 降级顺序：压力上来按档收缩缓存与图集，不是一律砍。

### 8. time — 日历换算

```rust
now() / local_day(secs, tz_offset) / local_hour(secs, tz_offset)
civil_date(epoch_day) / days_in_month(y, m) / weekday_monday0(day)
```

**时区一律是参数**——本层不问系统，「读者在哪个时区」是界面侧的事。

### 9. usage — 磁盘占用

```rust
measure(&areas) -> Usage
```

按去处（书库 / 日志 / 词典…）分类数一遍，存储屏那份数据。

### error — 地层错误

读盘与日志装配的错误类型；上面的层把它接进各自的因果链。

## 优化（现有实现里已经做了的）

- **零业务依赖**——往里加东西前先问「它与一本书有没有关系」，依赖图锁死。
- **时区是参数**——core 整体零进程环境依赖，测试不用改机器时区。
- **关停语义固定**——跑完已排的，不是立刻停；先后次序有后果的都收进 Services。
- **取消是协作式的**——作业自己分段看标志位，网络与作业共用同一套。
- **配置落盘原子**——临时文件替换，写一半断电也不坏配置。
