# 服务 API 设计

服务层：前端不直接碰管线与数据库细节，调服务。导入服务写得最全（第一条业务线），
其余服务各一小节。

## 服务一览

| 服务 | 干什么 | 入口 |
|---|---|---|
| 导入 import | 书怎么进来 | `submit_import` |
| 监听 watch | 文件夹新书自动导 | `WatchService::start` |
| 传书 transfer | 浏览器上传书 | `TransferServer::start` |
| 云盘 cloud | WebDAV / 百度 / 阿里取书 | `RemoteStore` / `Drive` |
| OPDS | 目录订阅取书 | `opds::fetch` / `parse` |
| 局域网同步 lansync | 两台设备互推书架与进度 | `lansync` 协议形状 |
| 朗读 speech | 从当前段开始读 | `engine()` |
| 词典 dictionary | 划词查词 | `StarDict::open` / `lookup` |
| 更新 update | 检查新版本 | `update::check` |
| 备份 backup | 书库快照 | `backup::create` / `list` |
| 同步 sync | 快照形状与对账 | `Snapshot` |
| 配置 config | 全局设置 | `Config` / `Resolved` |
| 翻译 / AI | 选区翻译 / 问答 | 各有一篇：翻译.md / AI.md |

## 导入服务（完整）

### 使用顺序（一屏看完）

```rust
// 1. 前端选好文件 → 包成来源
let source = Box::new(PathsSource::picked(paths));

// 2. 交给后台，handle 就是这批导入的全部接口
let handle = submit_import(&pool, source, book_dir, store.clone());

// 3. 收进度（两级：批 → 本）；不想等就 handle.cancel_and_wait()
for ev in handle.events.iter() { … }

// 4. 结束拿一份账
let report = ImportReport::tally(&outcomes);
report.summary();   // 「成功 3 / 已存在 1 / 拒绝 2（要口令 1、…）」
```

### API 一览

**来源——书从哪来**，三种折成同一个 `Source` trait，管线不问出处：

```rust
PathsSource::picked(paths)             // 文件选择器选的几个路径
PathsSource::picked_temporary(paths)   // 临时文件（分享/传书进来），导完要清理
UrlSource::new(url, transport)         // URL 下载（可 .with_headers）
CloudSource::new(drive, items)         // 网盘
```

```rust
pub fn submit_import(
    manager: &TaskManager,
    source: Box<dyn Source>,
    book_dir: PathBuf,
    store: Arc<Store>,
) -> TaskHandle<Vec<ImportOutcome>>
```

- 前端只调这一条；handle 给三样：进度事件、取消、完成值。
- 没有界面的驱动者（监听 / 传书）提交后用 `forward(handle, on_event)` 收事件。
- 结果：每本一本账（成功 / 已存在 / 拒绝 + 原因），`ImportReport::tally` 汇总。
- 章表重扫：`reindex(store, book_id)`——规则表换了、解析升级了之后用。

### 管线内部五步

前端不用管，写给讨论用：

1. **判格式**——`detect`，认不出拒绝导入；
2. **拷副本**——拷进书库，算 SHA-256 身份定副本文件名；
3. **解析索引**——`DocMeta` + 章表 + 封面，不产正文；
4. **落库**——register：书目行、章表行进 SQLite；
5. **落资产**——封面缩略图进书库资产区。

## 常驻服务收口（Services）

```rust
Services::new(pool)    // 作业池是各服务共用的去处
services.shutdown()    // 顺序死：停驱动者 → 关作业池 → 最后关库
```

常驻三样：导入作业池、文件夹监听、传书服务器。关停次序有后果（次序错了
后台线程会拿失效的连接写库），所以收在一处管。

## 其余服务

### watch — 文件夹监听

```rust
WatchService::start(config, store, queue, book_dir, on_event) -> WatchService
service.stop()
```

监听书库文件夹，新书落盘就提交导入（吃同一个作业池）。

### transfer — Wi-Fi 传书

```rust
TransferServer::start(config, on_file) -> Result<TransferServer>
server.addr() / pin() / urls() / stop()
```

设备起 HTTP 服务，局域网浏览器上传；`pin()` 是配对码；`on_file` 把落盘的
文件递给导入。

### cloud / opds / lansync / update — 出网一族

- 网盘三家的列、读、写、流式下载：`RemoteStore` 五个动作（见 网络.md）；
- OPDS：`fetch` / `parse` 出 `Feed`，相对链接按 feed 地址解析；
- 局域网同步：握手（证明持有密钥）+ 对账（`missing` 算对方缺哪几本）；
- 更新：`check(&transport, local_version)` 比版本、验 sha256 才认。
- 四个全是「收抽象接口」的形状，假实现离线可测。

### speech — 朗读

```rust
pub fn engine() -> Option<Engine>   // 没后端的平台回 None（入口不出现）
engine.ready() -> Option<bool>
engine.send(Command::…)             // 从哪段开始、停、调速
engine.events() -> Receiver<Event>  // 读到哪段、读完了
```

### dictionary — 词典

```rust
StarDict::open(dir) -> Result<StarDict>
dict.lookup(query, limit) -> Vec<Entry>
normalize_query(raw) -> String
```

StarDict 格式；热点词有 `dict::Cache` 收着。

### backup — 备份

```rust
Roots::from_config(&config)
backup::create(...) -> Result<Created>
backup::list(&roots) -> Vec<Entry>
backup::remove(&roots, path)
```

### sync — 同步快照

`Snapshot::new(device_id, exported_at)`、`retimed(...)` 对钟；
`BookEntry` 与各记录类型是对账的载荷形状。

### config — 配置

`Config`（版本化落盘）与 `Resolved`（合并默认后生效的那份）；
书内另有一层 `BookSettings`。

## 优化（现有实现里已经做了的）

- **落库封顶一批**——多批同时在飞也只跑一批，磁盘的账连着看。
- **拷贝与解析不持锁**——只有 register 那一小段持库锁，界面最多等几十毫秒。
- **两级进度**——批一级、本一级，进度条不跳。
- **协作式取消**——取消是标志位，拷贝 / 解析分段检查，不硬杀线程。
- **幂等关停**——shutdown 跑完已排的再收线程，重复调无害。
- **内容寻址去重**——同字节同身份，重复导入落「已存在」。
- **常驻服务收在一处关**——停驱动者 → 关池 → 关库的次序有人负责。
- **驱动者不占界面线程**——监听与传书在各自的线程上，事件转交回来。
