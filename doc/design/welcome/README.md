# 首次启动与「还没有内容」设计稿（compact 档）

六屏。两块放一份是因为它们说的是同一件事：**还没有东西可摆的时候这一屏长什么样**。
尺的逐条出处在 [`generate.py`](generate.py) 的文件头注释表里，共用的那份尺在
[`../_kit.py`](../_kit.py)。

| 文件 | 内容 |
| --- | --- |
| `01-welcome` | 首次启动：图标 + 标题 + 两颗按钮，整列居中，没有底栏 |
| `02-welcome-dark` | 首次启动的深色对照 |
| `03-empty-notes` | 笔记目的地：还没有内容时那两行字 |
| `04-empty-shelf` | 空书架：顶栏那根搜索框照在，架面换成那两行字 |
| `05-empty-search` | 搜不到：搜索框里留着那个词 |
| `06-empty-group` | 组里空：钻进展屏，底栏收起，那两行字居中在剩下的高里 |

## 这两块各自的几条

- **欢迎页那一格摆软件图标本体，不是线描图标**：实现现在是
  `Icon::new(IconName::BookOpen).large()` = 24 的线描书本，稿子改成
  `packaging/icons/folio.png` 那一份真资产缩到 64（生成时以 data URI 嵌进 SVG，
  所以 SVG 仍是真相源、重出即得）。放大到 64 有两个理由：带自己底板的方块标在 24 上会
  糊成一团，那本书与那枚书签只剩一片白；而这一屏的任务是「第一次打开，先认出这是哪个
  应用」，通用的书本形不担这个任务 —— 24 那一档是给列表行首的图标用的，不是给整屏唯一
  那颗标用的。**这是一处刻意偏离实现的设计改动**，落代码时要一起动 `welcome/mod.rs:75`。
  深色那一侧不需要另配一版图标：深绿底板落在 `#0a0a0a` 上边缘会软，但里面那本白色的书把
  形状撑住了（见 `02-welcome-dark`）。
- **欢迎页没有取消**：位置没确认过时，外壳画的是这一屏而不是主界面（`shell::AppShell`）。
  要么用系统文件夹选择器挑一个，要么一键用建议位置。它回答的是和书架那块「导入前确认」
  同一个问题，只是在时间上更早。
- **两端的控件都用普通按钮，不用浮层**：浮层在 Android 上现在点不住，而这一步是进应用的
  前提，点不动就等于进不去。
- **整列居中而不是靠顶**：图标、标题、按钮列三块，缝 16；两颗按钮之间 8。primary 表达的是
  「这一组决定里默认要走的那一条」，这里是真·选择文件夹；「使用默认位置」是 ghost。
- **`empty_state` 没有图标**：两行字在可用区正中，缝 8，标题 16 前景色、说明 14 次要色。
  加一枚图标是凭空的装饰 —— 那一屏要说的是「这里还没有东西」，一句话就够了。
- **说明那一行会折行**：组里空那一句（`shelf.group_empty_hint`）在三款手机上超过一行宽，
  而实现里那是一格普通 `div`，跟着宽度折。稿子按同样的规则折，最多两行。

## 量到的一条不符

`shelf.empty_hint` 现译是「用右边的「导入」选一本 epub、markdown 或纯文本」，而 compact 档那一条
顶栏上**没有叫「导入」的东西** —— 手机上是一根搜索框加一颗三点钮，「导入」藏在点开的那条菜单里
（见 [`../shelf/`](../shelf/README.md) 的 `06-import-menu`）。那句话在桌面上成立，在手机上把读者
往一个不存在的位置指。`04-empty-shelf` 照现译画，因为改文案是另一笔账。
