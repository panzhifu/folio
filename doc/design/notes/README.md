# 笔记设计稿（compact 档）

三屏：一条流、搜索有结果、深色对照。尺的逐条出处在 [`generate.py`](generate.py) 的文件头
注释表里，共用的那份尺在 [`../_kit.py`](../_kit.py)。

| 文件 | 内容 |
| --- | --- |
| `01-notes-flow` | 全库一条流：搜索框 + 「几条 · 出自几本」+ 批注卡，卡左缘一条色标 |
| `02-notes-search` | 框里有词：清除钮出场，眉标换成命中数，卡片同一形状 |
| `03-notes-dark` | 一条流的深色对照 |

## 这一档整格是稿先到

实现里 `NotesView` 只有 30 行，画的是一个空状态（`features/notes/mod.rs:18-30`，
「笔记 / 还没有添加过批注」）。而批注早就在库里，字段一个不缺：

```
annotations(id, book_id, anchor_json, note, color, style, stale, created_at, updated_at)
```

（`folio-core/src/store/annotations.rs:32-60`、`schema.rs:61`、v21 起有 `style` 那一列。）
所以这三张不是「优化一屏已有界面」，是**给一份已经在存的数据第一次画界面**。

## 主形状：全库一条流，不先选书

- **一条流按时间倒序**（`created_at DESC`）。理由：读者回到笔记这一格要的是「我当初划了
  什么」，那是一句**话**，不是一本**书**；先让他选书等于把问题换成「我在哪本书里划的」。
- **卡左缘那一条色标吃划线那五档**（`_kit.INK_COLORS`，顺序 = `ANNOTATION_COLORS`）。
  这一条同时回答两件事：这条是哪一档颜色、这一条到底划进了库没有（只有笔记没划线的
  情况不存在 —— 笔记挂在一条划线上）。
- **点整张卡跳回书里那一句**，卡上不摆第二颗「定位」钮。落点靠 `anchor::relocate`
  那四级降级链兜住（`plans/Locator.md` 记着它），书被删或锚点找不到时退到「这本书的
  那一章开头」，而不是弹一句「找不到」。
- **底栏「笔记」那一枚带条数**：高 14 的胶囊、10 号字、压在图标右上角。这几个数**没有
  出处可抄**（实现里没有徽标），是自定的，写进 `_kit.bottom_bar` 的注释里。分子是
  `Store::annotation_count`（`annotations.rs:176`，算好了但全 App 零调用点）。
- **搜索搜的是引文与你写的话**，不搜正文 —— 正文那一套在目录那屏的「全文」tab 里
  （`../reader/04-toc-sheet.svg`）。两个入口各答一个问题，不合并成一条框。
- **空的那一格不在这里画第二遍**：一条流都没有时摆的是
  [`../welcome/03-empty-notes.svg`](../welcome/03-empty-notes.svg) 那颗 `empty_state`，
  与空书架、搜不到同一份构件。

## 这一轮没画的，以及为什么

- **筛选（按书 / 按色 / 按画法）**：一条流在没有内容的时候摆三枚 chip 是空壳；等这一屏
  真的攒到几百条再决定筛什么。要加的话先加「按书」那一枚，它最可能先疼。
- **导出（Markdown / CSV）**：要新代码（写文件、选目录、九门文案），不属于「画一格就完」
  的那一类；先不摆入口，免得稿上有一颗按下去没有反应的钮。
- **批量删除**：与书架那一档同样的问题 —— 手机上没有可靠的多选形状（拖动入组那条已经
  被否决过），一条流里塞勾选框会把色标挤掉。
- **按书分组两层**：被「一条流」替掉。它的好处是能顺着书读，代价是每次进这一格都要先
  回答「我在哪本书里划的」，而那正是读者不记得的事。
