# 听书 API 设计

听书（合成朗读）：引擎侧只答「怎么念」，会话侧答「念什么」。**引擎机制住
folio-speech crate**（2026-11-11 起，从 folio-core::speech 原样搬来）；
`folio_core::speech::*` 与 `folio_core::{Command, Engine, Event}` 旧路径经模块别名
沿用。会话状态机（句级切分、跟读推进、跨章接力）住 folio-app 的
`reader::model::speech`——它咬着排版与阅读会话，不跟引擎走。

## 分工（一屏看完）

```rust
// 1. 挂引擎：进程级单例；探测结论经 Event::Ready 异步到达，不阻塞调用方
let Some(engine) = folio_core::speech::engine() else { /* 界面那格不出现 */ };

// 2. 一次一条 Speak，Done 里推下一段，不做预排；语速是语义值（常速 1.0）
engine.send(Command::SetRate(1.2));
engine.send(Command::Speak { text: 句文本 });
while let Ok(ev) = engine.events().recv().await { /* Begin / Done 推进会话 */ }
```

## API 一览

```rust
pub fn engine() -> Option<Engine>            // 进程级单例；探测终审失败后句柄留在槽里，下次调用重拉

pub struct Engine { … }                      // Clone 便宜（两条 channel 各一份）
impl Engine {
    pub fn ready(&self) -> Option<bool>      // None 还在探测 / Some(可用)——持久快照，不赌事件在管道里
    pub fn send(&self, command: Command)     // 引擎已退场时安静丢弃：可用性只看 Event::Ready
    pub fn events(&self) -> Receiver<Event>  // 唯一消费者（当前阅读会话）；接手前先抽干旧事件
}

pub enum Command { Speak { text: String }, Stop, SetRate(f32), SetPitch(f32) }
pub enum Event   { Ready(bool), Begin, Done }    // 念完与引擎报错归一成 Done，会话推进只认它

pub mod gate { reduce / rate_to_engine / pitch_to_engine }   // 纯函数，全平台 headless 可测
```

- **一次一条**：不做预排——预排要处理「读者翻页时队列里那几段怎么办」，一次一条
  把这个分支整个消掉。
- **停不依赖回调**：Android 的 cancel 回调有已知缺口（`rs/tts/Bridge` 的
  `onStop(String, Boolean)` 装箱参数是重载不是覆盖，故意不修），静音窗在
  `gate::reduce` 里——Stop 后一段时间内的回调不再触发推进；暂停/恢复都发 `Stop`，
  会话层自己记住当前句。
- **语义值**：`Config.speech` 的 `rate` / `pitch` 存常速 1.0 的倍数（区间
  `0.5..=2.0`，非有限值退常速），换算到引擎档住在 `gate`，会话层只递语义值；
  `auto_scroll` 开着才跟读翻页（关掉是「念它的，我翻我的」，高亮仍跟着念的那段走）。

## 平台矩阵

| 平台 | 后端 | 备注 |
|---|---|---|
| Linux | Speech Dispatcher（tts crate 的 linux 后端） | 构建要 libclang + libspeechd 头；运行时没 speechd 则探测失败，句柄 `None`，下次点开听书屏重试 |
| Android | 系统 `TextToSpeech`（JNI，tts crate） | 随包必须有 `rs/tts/Bridge` 类——`tts` 的 `JNI_OnLoad` 在 cdylib 加载那一刻就找它，R8 keep、manifest `<queries>`、gradle 排除 `libtts*.so` 与依赖同进同退，缺一样就是加载期 abort |
| macOS / Windows | 无 | 空实现恒回 `None`，界面对「这一格不存在」的画法是隐藏 |
| HarmonyOS | 无 | `not(target_env = "ohos")` 把 tts 挡在门外（它的 linux 后端要链接 speechd，OHOS sysroot 没有）；要等 NAPI / ArkTS（`@ohos.textToSpeech`）另起后端 |

- **会员门禁**：听书是会员功能。阅读页的圆形浮钮常在（不看引擎可用性），点开时
  双门禁 `speech_entry_visible() && premium`。
- **句柄为什么住专职线程**：`tts::Tts` 不能跨线程（内部 `Rc<RwLock<Box<dyn Backend>>>`），
  也不为此引 runtime——命令与回调合走一条 `async_channel`、事件走另一条，引擎线程
  用 blocking 两端收发，界面侧在 gpui 的 async 环境里 `recv().await`。

## 会话侧（folio-app，`reader::model::speech`）

- **句级 utterance**：按标点切句（`split_sentences`，长句再按子句收顶），一次念一句。
- **听的位置 = 读的位置**：`Done` 推进到下一句并跟随滚动；听就是读——落库走同一条
  `persist_locator`，阅读时长照记；离开阅读页（`Drop`）与换书都停听。
- **手动翻页不暂停听书**：翻到别处，念完当前句从新视口顶句接上。
- **跨章接力**：章尾念完等新章排版落地（100ms × 50 轮询）再起下一章。
- **开书不碰引擎**：引擎是进程级单例，成本在 `Tts::default()` 那一刻（JNI 线程与
  绑定），出场时机推迟到读者真的点开听书屏（`arm_speech` 只定位不开口）。

## 优化（现有实现里已经做了的）

- **探测异步到达**：`Tts::default()` 在引擎线程里调，调用方不被阻塞；探测失败可重试
  （Linux 上先跑起 speechd 再点一次就通）。
- **事件持久快照**：`Engine::ready()` 是快照不是赌事件还在管道里——会话一走那条
  事件就没了，新会话接手读这一格（真机上赌输了就是「听书按钮有时候不显示」）。
- **全部平台可测**：`gate` 的状态转移是纯函数，没有后端的 macOS / Windows 也
  headless 测「停不依赖回调」那条验收门。
- **实测语速折算**：界面上的快进退（±15 秒）与文稿滚动都按实测字/秒折算（0.7/0.3
  加权），不猜引擎的档位映射。
