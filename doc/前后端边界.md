## 一、判据

一条实现能不能搬到 core，看三条，**同时成立**才算：

1. **不实例化 gpui 类型**：`App` / `Context` / `Window` / `TextSystem` / `Entity` / `RenderImage`。
   作为**回调参数**出现不算（app 把它递给 core，core 只认自己定义的 trait）。
2. **输入能表达成 core 已有的类型**：`Document`、`RuleSet`、`Store`、`&[u8]`、`&Path`、纯数据。
3. **搬过去有测试价值**：能脱离窗口验证，且这些分支值得被验证（缓存、身份、降级、边界）。

用来校准的反例有两类：

- **反例 A（依赖 gpui 但形态正确）**：`reader/model/measure.rs` 全程依赖 `TextSystem`，
  但它 `impl folio_core::layout::Measure` —— 接口在 core，实现在 app。**这正是搬迁的模板**，
  不是搬迁的对象。
- **反例 B（纯逻辑但不该搬）**：`components/font_picker.rs:115` 的 `font_groups` 是纯分类，
  但输出是 gpui-kit 的 `SearchableGroup`、标题来自 locales。搬它等于把 UI 类型带进 core。

## 二、边界现状

| 层 | 在 core | 在 app 且应该搬 | 在 app 且不该搬 |
|---|---|---|---|
| 字体 | 清单 / 下载 / 装盘 / woff 解码 / `Document::fonts` 系列 / `Measure` trait | 别名解析、字体身份、子集化、名字表覆盖率、家族登记表、系统字体枚举策略（约 1280 行） | `measure.rs`、装字体的 Entity 状态机 |
| 统计 | 会话记录（`Store::reading_records`） | 分桶 / 补零 / 切区间 / 均值（`snapshot.rs` 606 行） | 那一屏的 tab 与卡片摆法 |
| 字典 | `StarDict` 解析、查词缓存 | 目录导入、ifo 发现、原子拷贝、id 生成（约 300 行） | 设置页的列表与开关 |
| 网盘 | `Drive` / `RemoteStore` / `Transport` / 两家 provider | 批量上传编排（约 80 行） | 目录浏览的导航栈、表单 Entity |
| 笔记 | 批注表、导出纯函数 | 跨书聚合与搜索匹配（约 150 行） | `NotesView` 的卡片与弹层 |
| 阅读 | 排版引擎、`Measure`/`ImageProvider` 端口 | 翻页决策（170）、页几何（257）、图集驱逐策略（约 120） | 会话状态机、手势、动画 |
| 同步 | 合并规则、快照格式、DAV/lansync 协议 | —（已经搬干净了） | 同步状态 Entity |

**结论**：这个仓的分层其实守得不错。真正越界的不是"逻辑写在哪"，而是**七块纯计算
被 UI 的测试条件绑住了** —— 它们现在要开窗口才测得到，而它们的分支（缓存命中、身份相同
不同 href、章界兜底、区间边界）恰恰是最该被反复验证的那些。

trait 草案（`core/src/text/mod.rs`）：

```rust
pub trait FontSink: Send + Sync {
    /// 交一批 sfnt 字节，回每份的家族名（顺序与入参对齐；整批失败回 `Err`）。
    fn add_faces(&self, faces: Vec<Vec<u8>>) -> Result<Vec<Vec<String>>, String>;
    /// 设备上已经注册着的家族名。`@font-face` 的 `local()` 与系统别名匹配都要它。
    fn known_families(&self) -> Vec<String>;
    /// 某一家族的某张脸有没有这个字（现在只问 `'m'`）。
    fn family_has_glyph(&self, family: &str, ch: char) -> bool;
}

pub struct LoadedFonts { pub aliases: BookFonts, pub stats: FontLoadStats, pub revision: u32 }

pub fn load_for(doc: &dyn Document, request: &FontRequest, sink: &dyn FontSink) -> LoadedFonts;
```

`FontLoadJob`（`book_fonts.rs:243`）一并搬 —— 它只是「跑一次并缓存」的 `Mutex<Option<_>>`，
把 `&TextSystem` 换成 `&dyn FontSink` 即可。

需要给 core 加三个依赖（现在都在 `crates/folio-app/Cargo.toml:73-83`，且已在 `Cargo.lock`）：
`skera 0.9`、`read-fonts 0.46`、`write-fonts 0.55`。`ttf-parser` core 已有。

**一个必须守住的点**：字体表版本（`FACE_EVENTS` / `families_revision`）是**进程级**的。
搬的时候只搬一份；两份额度会让排版缓存的失效键（`LayoutKey.fonts_rev`）出现两个真值，
症状是「装了字体但行宽没重算」，那是最难查的一类。

### 3.2 统计快照（606 行，0 gpui）

`stats/model/snapshot.rs`：`Snapshot::load`（226）把库里的阅读记录切成「当前区间」——

## 四、网络层统一

### 4.1 现状（好的那部分，别动）

`Transport`（`net/remote/mod.rs:23`）是**唯一**出网口：`request` / `download`（流式 + 取消）/
`upload`（可流式）。在这之上：

| trait | 位置 | 管什么 |
|---|---|---|
| `RemoteStore` | `net/remote/mod.rs:176` | 列 / 读 / 写 / 建目录 / 下载 / 传文件 |
| `Drive: RemoteStore` | `net/cloud/mod.rs:30` | 网盘再加一个 `label()` |
| `Translator` | `net/translate/mod.rs:122` | 翻译引擎（三只） |
| `Assistant` | `net/ai.rs:206` | AI 后端 |
| `LanLocal` | `net/lansync.rs:194` | 局域网同步的本机侧 |

opds / update / ai / translate / redeem / lansync / cloud 全部收 `&dyn Transport`，
离线可测。**这一层的基础是好的，不要重做。**

### 4.2 缺口 1：凭据刷新没有抽象（最该修）

证据：

- `expires_at` 全仓**只写不读**：`cloud/view.rs:882,907` 写入，0 处读。
- 401 之后的重试写在 UI，且两家各一份：`refresh_baidu`(544)+`settle_refresh`(559)，
  `refresh_aliyun`(582)+`settle_refresh_aliyun`(597)，两段几乎逐行同构。
- `BaiduDrive::new(token, …)` / `AliyunDrive::new(token, drive_id, …)` 只收**裸 token**，
  自己不会自愈，所以"过期"这件事永远由界面兜。

设计：

```rust
// core/src/net/cloud/auth.rs
pub struct Token { pub access: String, pub refresh: String, pub expires_at: i64 }

pub trait TokenSource: Send + Sync {
    fn cached(&self) -> Option<Token>;
    /// 换一对新的并**落盘**（refresh_token 会轮换，旧的立即作废）。
    fn refresh(&self) -> Result<Token>;
    /// 提前 60 秒判过期，过期先刷新。
    fn fresh(&self) -> Result<String>;
}

/// 装饰器：401 时刷新一次再重放，其余错误原样上抛。
pub struct AuthedStore<S: RemoteStore> { inner: S, tokens: Arc<dyn TokenSource> }
```

UI 侧那两对 `refresh_*` / `settle_refresh_*` 直接删掉，只留"刷新也失败 → 请重新授权"。

### 4.3 缺口 2：provider 没有注册表

证据：`Kind` 枚举 17 处 `match`（`view.rs:68` 定义，628/634/644/685/843/1093…），
全仓 `cloud.baidu` / `cloud.aliyun` 共 41 处引用，分布在 5 个文件：
`cloud/view.rs`、`settings/view/mod.rs`、`settings/pages/sync.rs`、`services/sync.rs`、
`infra/config.rs`。上一轮加阿里云盘改的就是这 5 个。

设计：

```rust
pub trait CloudProvider: Send + Sync {
    fn kind(&self) -> &'static str;                       // 稳定标识，进日志与配置
    fn label_key(&self) -> &'static str;                  // 界面文案走 locales
    fn configured(&self, cloud: &Cloud) -> bool;
    fn build(&self, cloud: &Cloud, t: Arc<dyn Transport>) -> Option<Box<dyn Drive>>;
    fn build_sync(&self, cloud: &Cloud, t: Arc<dyn Transport>) -> Option<Box<dyn RemoteStore>>;
    fn auth(&self) -> Option<&dyn AuthFlow>;              // 有 OAuth 的才有
}

pub fn providers() -> &'static [&'static CloudProvider];
```

`view.rs` 从三处 `match` 变成一个循环；加第四家 = 新增 impl + 注册 + 文案键，
不再碰 `Kind`。**这是"加一家网盘"这件事的收敛点。**

### 4.4 缺口 3：错误映射三份

- `baidu.rs:511 check` / `:525 errno_error`（`errno` 码表）
- `aliyun.rs:418 check` / `:445 body_error`（`code` 码表）
- `dav.rs:273 check_status` / `ureq.rs:153 status_error`

**统一**：只保留 `net::remote::Error` 这一套语义（已有），各 provider 提供一个
`fn map_error(code: &str, status: u16) -> Error` 纯函数。界面那层 `view.rs:925 failure_of`
（把 `RemoteError` 折成"读者能做什么"三档）留在 app，但只留一份、对所有 provider 生效。

### 4.5 缺口 4：认证头构造不统一

WebDAV 走 `Authorization: Basic`，阿里云盘走 `Bearer`，百度把 token 放 query。
**不建议**做 `HttpAuth` trait（百度那条必须改 URL，抽象会变味）：做两个具体类型
（`BasicAuth` / `BearerAuth`）+ 百度那个 `with_token(url)` 助手，够用且不骗人。

### 4.6 缺口 5：没有重试/退避 ✅

全仓只有"401 刷新一次"，没有 429/5xx 退避。分片上传、翻译、检查更新都会撞限流。
**已加** `net/remote/retry.rs` 的 `Retrying<T: Transport>` + `RetryPolicy { attempts,
base, max_delay }`，`ureq::shared()` 默认套上。判据：429 / 408 / 5xx 对全部方法重试；
连接类错误只重试幂等方法；流式下载与 4 MiB 以上的上传不重试（没有断点续传）。
两次之间的等待走注入的 sleeper，测试不真的睡。

### 4.7 缺口 6：token 泄漏面（安全，小活，建议先做）

`Request` 的 `Debug` 会原样打出 URL，而百度把 `access_token=` 拼在 query 里
（`baidu.rs:104,180,216,261,425`）。任何 `tracing::debug!("{req:?}")` 都会把 token 写进日志。
修法：手写 `Request` 的 `Debug`，把 `access_token=` / `client_secret=` 之后的值换成 `***`；
拼 token 的 URL 统一走一个 `with_token()` 助手（顺手也是 4.5 的统一点）。

### 4.8 缺口 7：文档漂移

`net/remote/mod.rs:5` 仍写着"真正能把字节发出去的那份实现要用 `App::http_client()`，
只能住在 app 侧"，而实际的 `UreqTransport` 就在 core（`remote/ureq.rs`）。
下一任维护者照着这句做，会把传输层错误地搬回 app。**改注释。**
