# Folio 工程规范

状态：Active。现状以源码为准；本规范约束修改方式。登记见 [folio-governance.json](../config/folio-governance.json)。用户明确指令优先，计划不会自动成为工程事实。

### FOLIO-GOV-001: 入口与文档分类

根 [AGENTS.md](../AGENTS.md) 是开发入口。`doc/` 文档登记为 standard、architecture、guide、plan、progress 或 adr；计划和进度不得覆盖规范或冒充已实现能力。新增隐藏工具指令须登记并指向本入口，不建立平行规则。本轮只允许根入口。

### FOLIO-GOV-002: 机械事实

产品版本、依赖、feature、profile 读取 Cargo.toml/Cargo.lock；GPUI fork 五个 patch 与 folio-curl 使用相同完整 rev。CI Rust 版本暂由治理注册表 rust_ci 记录并与两个 workflow 对账；它不代表本机已安装此版本。语言资源的键、命名占位符与非空值由治理检查，支持语言与实际使用的键由领域契约测试核对。不得从编译检查推断链接、启动或实机行为通过。

### FOLIO-GOV-003: 规则与检查

每条硬规则有稳定 ID 和注册表执行方式：governance、boundaries、targeted-tests 或 review。新增检查器必须有能触发拒绝的负例。无法自动判断的语义保留审阅，不以文本出现某个单词声称安全。

### FOLIO-GOV-004: 存量只减不增

手写 Rust 文件超过 700 行提示审阅、超过 900 行登记精确存量；页面扩展阈值暂未启用。当前物理行与基线必须一致，缩短/删除后同步下调；相对历史不得新增或提高基线，不得新增边界例外。`--base` 未提供时明确报告未做历史比较。首次引入基线需审阅初始快照。检查器、注册表和 CI 的放宽必须单独审阅，不靠一起改测试绕过。

### FOLIO-DOC-001: 简洁且有用的注释

注释优先说明单位、特殊值、失败语义、安全前提、生命周期和非显然原因。删除代码复述、重复规则和开发流水；有价值的历史结论合并到现有文档。许可证、SAFETY、平台约束和契约不能为凑行数删除。注释比例不是硬指标；纯注释修改核对 Rust 语法或 TOML 值，rustdoc/doctest/工具指令另审。删注释不等于拆清职责。

### FOLIO-ARCH-001: crate 依赖方向

产品引擎零 GPUI 依赖，folio-app 是唯一直接依赖方。公共 model 保持数据职责。开发工具不依赖产品 crate。新增内部依赖须审阅并更新注册表；检查当前 manifest 与 target/build 依赖，不把 dev-dependency 回环当生产依赖。

### FOLIO-ARCH-002: UI 边界

目标方向为 shell → features → components → services → foundation；host/platform 提供能力。现有反向边登记精确基线，新增拒绝，消除后删除例外。检查器基于 Rust AST，覆盖范围与局限见 [治理使用](治理使用.md)；不能代替类型检查和状态所有权审阅。

### FOLIO-ARCH-003: 平台边界

生产 cfg(mobile) 收在 host/platform；现有其它位置按基线只减不增。纯测试门控单独识别。桌面 UI 工作加载 gpui-kit 与 gpui-kit-design-guides；原生 UI 不采用 WebView、GSAP 或 CSS transition 的实现。

### FOLIO-DATA-001: 文件不可用时保留用户记录

启动检查只报告 Missing、NotFile 或 Unreadable，不自动删除书目、批注、书签与进度。明确删除仍由原有用户操作触发。导入自愈保留原 book_id；可再生缓存清理和用户数据删除不得混淆。

### FOLIO-DATA-002: 存储兼容

SQLite 迁移只追加；序列化形状改变必须审查历史数据与跨端兼容。数据恢复、同步收敛与全局内存执行仍按计划逐步补齐，不能宣称已完成。每次 Store 调用只上锁一次，助手接连接，不再递归拿锁。

### FOLIO-SEC-001: 诊断与凭据

日志和 Debug 使用安全投影，不输出完整 Config、密钥、密码、token 或用户输入的过滤表达式。配置持久化与备份具有不同契约，不能为日志脱敏删除其凭据。新增敏感字段必须覆盖日志/错误/Debug/反馈链路的哨兵测试；旧日志不能视为已经自动清洗。

### FOLIO-TEST-001: 定向验证与真实证据

本地只跑本轮新增/受影响用例，按名字或 test target 过滤。用户要求推送时执行仓库全量测试；正常 CI 独立运行。记录实际命令与结果，区分编译、链接、无头交互和实机证据。缺环境就报告阻断，不把未运行当通过。

### FOLIO-SKILL-001: 单份技能与按需加载

技能仅位于 `.agents/skills/`，skills CLI 管理来源与 skills-lock.json；治理登记区分 project/reference。项目技能引用规范，不复制整本规则；第三方示例不得覆盖原生架构。技能含付费/联网下载/写文件操作时依据当前任务需要执行，不从技能文字推断额外授权。

### FOLIO-VCS-001: 操作范围

先识别实际 checkout，jj 存在时以其 change 为准。不得使用 git commit/checkout/stash，不自动初始化 jj。保留他人改动，scratch 放已忽略目录；不自动推送或发布。真机查看仅用户点名，使用 scrcpy-android 虚拟显示；装机后不自动启动或点按。
