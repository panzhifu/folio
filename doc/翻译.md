# 翻译与词典 API 设计

选区翻译：一个引擎 trait + 三只引擎（Google 免 key、OpenAI 兼容、DeepL）。
本地词典：StarDict 解析与多词典库查词。两条「查」的路同住 **folio-translate crate**
（2026-11-11 起，机制从 folio-ai::translate 与 folio-core::dict 原样搬来——AI 问答
留在 folio-ai，见 [AI.md](AI.md)）；`folio_core::net::translate::*` 与
`folio_core::dict::*` 旧路径经 shim / 模块别名沿用——按配置挑引擎的分发就在那个
入口层（`net::translate::configured`），词典源列表由 app 按配置拼好递进来。

## 翻译

### 使用顺序（一屏看完）

```rust
// 1. 按配置挑引擎；永不失败——没配就回 Google 免 key 那只兜底
let translator = configured(&config);

// 2. 译一段：from 给 "auto" 让引擎自己检测
let t = translator.translate(&transport, "hello", "auto", "zh-CN")?;
```

### API 一览

```rust
pub fn configured(config: &TranslationConfig) -> Box<dyn Translator>   // 入口层在 folio-core

pub trait Translator: Send + Sync {
    fn cache_key(&self) -> String;   // 缓存表 provider 列的键；密钥不进键
    fn translate(&self, http: &dyn Transport, text: &str, from: &str, to: &str)
        -> Result<Translation, TranslateError>;
}
```

- 三只引擎：`GoogleTranslator`（免 key）、OpenAI 兼容（与 AI 共用地址与密钥）、
  DeepL。
- `source_hash(text)`——译文缓存的键，落库走 `store::translations`（翻译缓存表）。
- `Translation` 是译回的那一份（原文 / 译文）；网络、鉴权、响应形状的问题
  都以 `TranslateError` 分档报。
- `language_name(BCP-47 码)` → 语言名表：翻译请求与 folio-ai 的提示词共用一份真源。

## 词典（`dict` 模块）

### 使用顺序（一屏看完）

```rust
// 1. 查词：sources 由 app 按配置拼好（词典源 + 盘上目录），后台那趟不再读全局配置
let hits = lookup_in(&sources, "heck")?;          // 跨词典合并，进程级 Cache 挡住重复打开

// 2. 导入：把一个文件夹原子搬进词典区（先落临时名再改名，失败整趟撤掉）
let imported = import_folder(src, &dicts_dir, &taken)?;

// 3. 删除：连目录带缓存一起清；目录已不在算成功
remove_folder(&dicts_dir, &id)?;
```

### API 一览

```rust
pub fn lookup_in(sources: &[Source], query: &str) -> Result<Vec<Hit>>
pub fn import_folder(src: &Path, root: &Path, taken: &BTreeSet<String>)
    -> Result<Vec<ImportedDict>>
pub fn remove_folder(root: &Path, id: &str) -> Result<()>
pub fn normalize_query(raw: &str) -> String        // 大小写 / 空白归一
pub fn cache() -> &'static Mutex<Cache>            // 进程级词典缓存（全仓只此一份）
pub fn clear_cache()                               // 删词典后由 app 调，把缓存失效掉

pub struct StarDict { … }                          // 一本打开的词典：open(dir) / lookup(query, limit)
pub struct Meta { bookname, wordcount, version, offset_bits, sametypesequence }   // .ifo 书目
pub struct Entry { word, phonetic, meaning }       // 一条可展示的词条（释义已去标签、解码实体）
```

- **内存账**：打开词典把 `.idx` 与 `.dict` 整个读进内存再排序词表——查词要零延迟与
  跨词典合并，分块随机读让每次查词都回磁盘，收益在手机上抵不过那一跳。上限
  `MAX_IDX_BYTES` 32 MiB / `MAX_DICT_BYTES` 256 MiB，超了在导入那一步就拒，
  不运行到一半 OOM。
- **缓存进程级**：查词一次可能跨几本词典，重复打开几十 MB 的文件代价全落在
  「换一本书再查同一个词」上；删除词典后由 app 调 `clear_cache` 失效掉。
- **零网络、零 folio 依赖**：机制只有磁盘与内存（flate2 解 gzip 一条外部依赖），
  离线可用；与在线翻译同 crate 不同模块，互不依赖。
- **错误自持**：`DictError`（Io / Dictionary 两条，Display 文案与搬来前 core 的
  `Error::Io` / `Error::Dictionary` 同形状）——core 的伞枚举不再有 `Dictionary`
  变体；导入失败的「这一本词典坏了」提示与删掉重导的路径照旧（`why` 一句话随错误走）。

## 优化（现有实现里已经做了的）

- **三只引擎同一 trait**——换引擎调用方零改动，假传输离线可测。
- **译文缓存落库**——同一句不翻第二遍，`source_hash` 当键。
- **与 AI 共用一格配置**——地址与密钥一份，读者不填第二遍。
- **Google 免 key 兜底**——什么都没配也有翻译可用。
- **导入原子化**——先落 `.import-<id>` 再改名，失败整趟撤掉；重复导入拿 `-2` / `-3`
  后缀而不是覆盖上一本（`taken` 集合由调用方给，同一批里新导入的 id 也占住）。
