# 翻译 API 设计

选区翻译：一个引擎 trait + 三只引擎（Google 免 key、OpenAI 兼容、DeepL）。
AI 是它的兄弟篇（同一套形状），见 AI.md。**机制住 folio-ai crate**（与 AI 同 crate）；
`folio_core::net::translate::*` 旧路径经 shim 沿用——按配置挑引擎的分发就在那个入口层。

## 使用顺序（一屏看完）

```rust
// 1. 按配置挑引擎；永不失败——没配就回 Google 免 key 那只兜底
let translator = configured(&config);

// 2. 译一段：from 给 "auto" 让引擎自己检测
let t = translator.translate(&transport, "hello", "auto", "zh-CN")?;
```

## API 一览

```rust
pub fn configured(config: &TranslationConfig) -> Box<dyn Translator>

pub trait Translator: Send + Sync {
    fn cache_key(&self) -> String;   // 缓存表 provider 列的键；密钥不进键
    fn translate(&self, http: &dyn Transport, text: &str, from: &str, to: &str)
        -> Result<Translation, TranslateError>;
}
```

- 三只引擎：`GoogleTranslator`（免 key）、OpenAI 兼容（与 AI 共用地址与密钥）、
  DeepL。
- `source_hash(text)`——译文缓存的键，落库走 `store::translations`（翻译缓存表）。
- `Translation` 是译回的那一份（原文 / 译文）；网络、鉴权、响应形状的问题
  都以 `TranslateError` 分档报。

## 优化（现有实现里已经做了的）

- **三只引擎同一 trait**——换引擎调用方零改动，假传输离线可测。
- **译文缓存落库**——同一句不翻第二遍，`source_hash` 当键。
- **与 AI 共用一格配置**——地址与密钥一份，读者不填第二遍。
- **Google 免 key 兜底**——什么都没配也有翻译可用。
