# 治理工具

`tools/folio-xtask` 是开发工具 crate，不依赖产品或 GPUI。入口：

```text
cargo xtask governance [--base <git-ref>]
cargo xtask boundaries
cargo xtask snapshot
cargo xtask change-plan
cargo xtask i18n
cargo xtask release-check [--base <git-ref>] [--artifacts <dir>]
cargo xtask comment-check <base> <path>...
```

governance 核对文档登记、规则 ID、入口链接、技能登记、内部依赖、GPUI rev、CI 版本、语言资源、文件规模和 UI 存量。`--base` 增加历史基线比较；第一次引入基线报告需要审阅，后续只能降低。snapshot 仅输出 JSON，不替用户写入基线。change-plan 输出实际 checkout 状态与验证类别，不自动执行测试。

i18n 单独执行语言资源检查，与 governance 共用实现：以英文为参照核对所有 TOML 的键、命名占位符与非空字符串，拒绝空覆盖、重复展平键与畸形占位符。支持语言枚举与源码实际使用的键仍由 core/app 的现有契约测试验证；不把资源一致性当作翻译质量或界面适配证据。

release-check 核对 Cargo/Android 版本、minSdk、许可证/图标/TTS 桥与 R8 配置；提供 `--base` 时检查 Android 版本号递增，提供 `--artifacts` 时验证目录内全部普通文件与 SHA-256 清单一一对应。缺资产报告实际路径。日常 Windows/macOS CI、Release 的版本闸门和发布前下载产物都调用它。签名、安装、升级和包内容仍由目标平台流程验收；源码检查不代替这些证据。

boundaries 使用 AST 检查 UI 引用和生产 mobile 条件。宏内部生成的依赖、完整 rustc 名字解析、动态调用与跨 crate 传递依赖不由此工具证明；manifest 检查负责直接生产/target/build 依赖，正常构建和现有 core 契约测试继续保留。baseline 记录当前遗留，不宣称单向分层已经完成。

comment-check 解析 TOML 值或 Rust AST（忽略 doc 属性）比较。普通字符串内的 `//` 不会当注释删掉；doc test、宏消费的文档、工具指令和许可证仍需审阅。它不证明任意源文件修改行为等价，不应拿来替代逻辑变更测试。

技能检查核对入口/lock 元数据及项目路由，不将 computedHash 存在等同于已经重算第三方包完整性。技能内容变更按 CLI 同步 lock；完整内容校验和前端 YAML 校验在安装验收执行。检查本身不联网、不安装、不读取用户凭据。

本地定向验证按 AGENTS.md。本工具为 bin，检查器改动使用 `cargo test -p folio-xtask <filter>`。CI 的快速治理 job 独立于产品构建，但 Cargo workspace 解析仍可能需要产品依赖元数据；缺少缓存时如实报告。
