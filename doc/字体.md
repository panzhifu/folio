# 字体 API 设计

字体域的两条线同住 **folio-fonts crate**（2026-11-12 起，机制从 folio-core::text 与
folio-core::fonts 原样搬来）；`folio_core::text::*` 与 `folio_core::fonts::*` 旧路径经
模块别名沿用。它不认识配置文件与书库：字体根目录由调用方递进来（
`folio_base::paths::fonts_dir` 在 core 那侧拼装），错误自持（`FontsError`，原
`folio_core::Error::Font` 变体删除）。

## 两条线（一屏看完）

```rust
// ── text：随书字体的装载（排版前那一脚，app 的书内字体服务走这条）──
// 1. 从书的 @font-face 规则起一份装载作业；doc 给「字节从哪儿现取」
let job = folio_core::text::load::FontLoadJob::new(doc.clone(), FontRequest::from_rules(&rules));

// 2. 跑作业：子集化后的字节经 FontSink 注册进 gpui 的 TextSystem（实现住在 app），
//    拿回「声明名 → 真实家族名」的别名表与一份统计
let (book_fonts, stats) = job.run(&sink);

// ── fonts：读者自己装的字体库（设置页的字体管理走这条）──
let item  = folio_core::fonts::manifest().item(id)?;           // 内置清单（随二进制走）
let path  = folio_core::fonts::download_item(item, &*transport, &root, &cancel, |n| …)?;  // 下载
let path  = folio_core::fonts::install_copy(&src, &root, &id, &name)?;                    // 导入
folio_core::fonts::remove(&root, &id)?;                                                   // 删除
```

## `text` —— 随书字节的机制

- `load` —— **加载管线**：`@font-face` → 身份去重（`FontId`，crc32 + 长度）→ 读字节
  （`Document::fonts` / `font_refs` / `read_font`，EPUB 别名缓存命中时零解压）→ 子集化
  （skera，按全书可见字符集 `font_charset` 裁）→ 改名（挂 `#folio` 标记防与系统字体串）
  → 注册 → 别名表。gpui 的接触点收进 [`FontSink`] 一个 trait：接口在这一层，实现
  （`TextSystemSink`）在 app —— 与 folio-render 的 `Measure` 同一条边界画法。
- `families` —— **家族登记表**（进程级）：随书字体注册过哪些名（`note_book_family`）、
  用户字体注册过哪些名（`note_user_family`）、哪个名字当前**可用**（`usable` ——
  内嵌字体卸载后回退链要摘掉它）。`families_revision` 是整表的版本号，度量缓存靠它失效。
- `names` —— 字节 name 表的**拉丁覆盖**判定（`latin_by_family`）：这家族有没有拉丁字，
  排回退链时拉丁文不再借中文字体的拉丁区。
- `scan` —— 盘上字体文件的扫描判据（`is_font_file` / `scan_verdict`）：系统字体目录
  变了要不要重扫，由它说。

## `fonts` —— 用户字体库

- `manifest()` —— **内置清单**（`font_manifest.json` 随二进制走，`include_str!`）：改
  清单 = 随版本发布，不热更。每项钉 tag 的 GitHub 直链 + 发版时实测的 `size`，下载完
  对不上当场拒（`parse` 守两条底线：id 不空不重、直链必须 https）。
- `download_item` —— **下载半程**：先落 `<根>/.part-<id>/`，完成后整体改名 —— `<id>`
  要么完整出现要么不出现；主源失败按序换镜像，**取消不换源**（那是读者的话），大小
  核对不过当场拒。传输由调用方递进来（`folio_net::ureq::shared` 或测试里的假传输）。
- `install_copy` / `dir_id` / `unique_id` / `remove` / `wash_file_name` —— **导入与
  删除**：与词典同形（一份字体一个目录，重名加后缀、删除收敛在目录这一层）。
- `font_kind` / `decode_font_file` —— **魔数识别与解回 sfnt**：woff / woff2 解回、
  sfnt 原样、认不出回 `None`。自装字体的注册入口（开机重注册与装完当场注册）共用
  这一脚；五类判据与 folio-format 的 `woff(2)::is_*` 同源。

## 错误分档

`FontsError` 三条：`Font { path, why }`（清单 / 大小核对 / 解不出来——设置页按「这一份
装坏了」提示并让读者删掉重装）、`Io { path }`（落盘读写）、`Cancelled`（读者取消——
**不是失败**，界面回 Idle；按类型分档，别匹配文案）。与 `folio_format::Error` /
`DictError` 同一条口径：自持、带上下文、底层原因留在 `source` 链上。

## 依赖与平台

skera / read-fonts / write-fonts / ttf-parser **必须留在主依赖区**：`text::load` 不分
平台，Windows / macOS 也要用（从前误放进平台门控段，桌面两端编不过）。`fonts` 的下载
走 folio-net 的同步 `Transport`，与 `net::update` 同一条理由：出网的作业跑在后台线程上，
「一个请求流到底」用阻塞读最直白。
