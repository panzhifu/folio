name: folio-data-integrity
description: 修改 Folio 的 SQLite、数据删除、导入自愈、备份恢复或跨设备同步时，验证兼容性与失败后的数据保全。
---

遵循 [AGENTS.md](../../../AGENTS.md) 与 [工程规范](../../../doc/工程规范.md)，读取 [储存](../../../doc/储存.md)、[服务](../../../doc/服务.md) 及受影响实现。测试使用合成数据与临时库，不读取或删除用户真实书库。

定位数据 owner 与写入顺序：Store 一次公开调用拿一次锁，内部助手接连接；文件复制/解析不持库锁。缺失、非文件、无法读取是不同状态，`unavailable_sources()` 只报告，不能变回启动自动删记录。导入自愈应保留 book_id、批注、书签与进度，失败只回滚本次操作。

SQLite 迁移只追加，改 serde/快照前读旧版 fixture 和消费者。备份配置可能包含凭据；日志使用安全投影，持久化与备份不能被同一“脱敏”逻辑破坏。恢复的磁盘与凭据契约见 [恢复 ADR](../../../doc/adr/2026-11-18-备份恢复激活与凭据.md)：独立副本准备完成后，下次启动在配置、Store、服务之前激活，不能在线替换活动库。

恢复修改覆盖隔离解包、实际提取路径/体积/版本校验、启动选择、激活前保留原数据和断点重入。ready 后重试不能覆盖新写入，启动选择出错不能静默回旧库。同步修改先证明同秒冲突、乱序、重复、删除/恢复与时钟偏差；不得用旧快照 exported_at 平移到当前时间来伪造新写入。v1 形状兼容不等于混用旧冲突规则的客户端仍可收敛。

选择实际受影响用例验证失败后的记录，而不是只断言某个助手被调用。现有缺书保全入口为 `cargo test -p folio-store --lib unavailable_sources`；其它用例先检索真实名称。没有运行的恢复/跨端测试不能宣称通过，常规变更不默认全量。
